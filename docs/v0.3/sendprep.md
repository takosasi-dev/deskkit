# SendPrep(共有前クリーナー)— v0.3.0 の実装メモ

仕様書: `SendPrep_共有前クリーナー_仕様書.md`(リポジトリ外)。担当範囲: `deskkit/modules/sendprep/**`・`tests/modules/sendprep/**`・この文書。

## 1. 構成

仕様書 §2 のファイルに加えて、次の2つを置いた。

| ファイル | 中身 |
|---|---|
| `config.py` | 設定(§9)の既定値・検証・プリセットの追加/名前変更/上限変更/削除 |
| `_win32.py` | ctypes の Win32(既知のフォルダ「ピクチャ」「送る」、`IShellLinkW` でのショートカットの作成と読み取り)。`ShellLinkApi` の Protocol の背後に置き、テストでは偽物に替える |

`create()` と import の時点では Pillow・numpy・winrt・pi-heif を読まない(NFR-5。`tests/modules/sendprep/test_page.py::test_nfr5_*` で子プロセスを起こして確かめている)。

## 2. 機能要件の実装状況

FR-1〜FR-23 はすべて実装した(未実装なし)。

| FR | 実装 |
|---|---|
| FR-1・2 | 画面全体がドロップを受ける(点線の枠は見た目)。フォルダは直下のファイルだけ。「ファイルを選ぶ」は複数選択 |
| FR-3・4 | キューは未完了 200 件まで。超えた分は積まずに注意書き。対応していない形式は数だけ出す |
| FR-5 | 既定の4つは固定。追加は `custom-<連番>`、1〜500MB の整数、5 個まで。名前変更・上限変更・削除 |
| FR-6・9 | JPEG・PNG・WebP はバイト列の書き換え。書いたあとに読み直して検証し、通らなければ出力を消して失敗 |
| FR-7・8 | 1MB = 1,000,000 バイト。元が上限以下なら縮めない。収まらなければ出力を残さない |
| FR-10〜13 | 伏せ字エディタ(別ウィンドウ)。文字認識は裏で1回、候補は点線で出すだけ。使えなければ FR-13 の文 |
| FR-14〜16 | ffmpeg(h264_mf + AAC)。ビットレートの段階・作り直し・進捗・中止・初回の展開と照合 |
| FR-17・18 | 1件の失敗で止めない。全件の後に「完了 N 件・失敗 M 件」「フォルダを開く」「出力をまとめてコピー」(CF_HDROP) |
| FR-19 | トレイ(とクイックアクション。トレイ項目は host が自動で候補に入れる)に「クリップボードの画像を整える」 |
| FR-20・21 | 「送る」のショートカット。`handle_cli(["open", *paths])` で積んで `ctx.show_page()` |
| FR-22・23 | `usage()` と `diagnostics()`(ファイル名・パスを入れない) |

## 3. 仕様からの変更点・決めたこと(理由つき)

1. **JPEG で消す範囲を広げた(S-1)**: APP1・APP13・COM に加え、APP0(JFIF/JFXX)・APP2(ICC_PROFILE)・APP14(Adobe)以外の APPn(MPF・メーカーの独自データなど)と、EOI の後ろに付いたデータ(iPhone などの付属画像。付属画像は自分の Exif を持つ)も消す。FR-6「メタデータが残ってはならない」を満たすため。検証(FR-9)も同じ範囲で見る。
2. **BMP は PNG に変換する(S-3)**: 仕様は「JPEG(写真)または PNG(透過あり・GIF)」。BMP は写真よりスクリーンショットが多く、可逆のまま出す方が期待に合う。上限を超えるときは S-5 のとおり JPEG に変わる。HEIC は仕様どおり JPEG(透過があれば PNG)。
3. **WebP を縮めるときは WebP のまま S-4 の探索**(仕様に記述なし)。アニメーション WebP は §10 のとおり1枚目を PNG。
4. **Orientation**: 再エンコードした JPEG にも Orientation だけの Exif を付ける(FR-6)。伏せ字を焼き込むときは、エディタに見たままの向きで出すため画素を回してから焼き込み、Orientation の Exif は付けない(向きは画素に反映済み)。
5. **動画の「位置情報を消すだけ」(S-9)**: `-map 0:v -map 0:a?` で映像と音声だけを残す。iPhone の MOV は位置情報を時系列のデータトラック(mebx)にも持てるため、データ・字幕トラックは落とす。
6. **動画の長さが読めないとき**: 失敗にするのは再エンコードが必要なとき(ビットレートの計算に要る)だけ。作り直さない(S-9)ときは長さが無くても進める(進捗の % は出ない)。
7. **VQ-2(h264_mf が使えない PC)**: 上限を超える動画は「この PC では動画を縮められません(「位置情報を消すだけ」は使えます)」で失敗にし、出力は残さない。共通仕様 VQ-2 の案「位置情報の削除だけを行う」だと上限を超えたファイルができ、FR-7(必須)に反するため。使えるかは最初の再エンコードの前に、パイプから 64x64 の5フレームを流して1回だけ確かめる(`-f lavfi` は使わない)。
8. **音声**: AAC 128kbps・2ch(仕様に値なし)。
9. **ffmpeg の展開先の `<ffmpeg の版>`**: zip には版の情報が無いので、`ffmpeg.sha256` の先頭 16 桁をフォルダ名にする。古い版のフォルダ(16 桁の16進の名前で、中身が自分の展開物だけ)は消す。照合に失敗した exe は1回だけ展開し直し、それでも合わなければ照合失敗。
10. **zip の形式**: `zipfile` が読めれば何でもよい(配布は LZMA、テストは STORED)。zip の中の `ffmpeg.exe` はフォルダの中にあっても名前で見つける。
11. **操作記録(§9)**: 伏せ字の焼き込みは、元のジョブとは別の行(`kind: "image"`・`redactions > 0`)として書く。「整えた件数」は成功したファイルのジョブとクリップボードを数え、焼き込みの行は数えない。「伏せ字を焼き込んだ件数」は `redactions > 0` の成功行。クリップボードの行は `preset: "meta"`、`in_bytes`/`out_bytes` は画素数 × 4(ファイルが無いため)。
12. **キューの一覧**: 全部終わった後に新しく積むと、終わった行を片づけて新しい一覧にする(完了のまとめもその一覧のもの)。同じファイルの判定は「まだ終わっていない行」とだけ比べる(整え直しができるように)。
13. **「送る」**: 同じ名前の、自分が作っていないショートカットがあるときは、消さないだけでなく上書きもしない(「追加しませんでした」と出す)。`DESKKIT_HOME` があるとき(テスト・自己検査)は、その下の `SendTo` を使い、本物の「送る」に触れない。
14. **文字認識の候補**: 実測で、メールアドレスの `r` が `「` と、`+81` の `+` が `十` と読まれた。メールの名前の部分に `「」|` を、国番号の前に `十` を許した。日本語は1文字ずつ単語に分かれるので、空白でつないだ文字列と空白なしでつないだ文字列の両方を調べる。
15. **完了の通知**: Control Center を開いていないときだけ出す(画面を見ているときは画面のまとめで足りる)。
16. **エディタでの伏せ字の種類の切り替え**は、設定の既定(`redact_style`)にも保存する。モザイクの見た目はエディタでは網掛けで示し、実際のモザイクは焼き込みで作る。

## 4. 実測(§8。2026-09-25、この開発 PC)

| 項目 | 結果 |
|---|---|
| 12MP JPEG(4000×3000、合成、4.8MB)「Discord(10MB)」 | 0.12 秒(上限以下なのでメタデータ除去だけ。FR-8) |
| 同「小さめ(3MB)」 | 0.25 秒 → 2.59MB |
| 12MP JPEG(ノイズの多い合成、12.8MB)「Discord(10MB)」 | 0.51 秒 → 7.61MB |
| 同「小さめ(3MB)」 | 1.17 秒 → 2.97MB |
| 1920×1080 の PNG(30 行の文字)の文字認識 | 認識 0.61 秒・候補の判定 0.004 秒(候補 120 か所 = 仕込んだ数どおり) |
| 1 分 1080p の HEVC・MOV(kvazaar で作った合成、30fps、8Mbps、60.8MB)「Discord(10MB)」 | 6.2 秒 → 9.52MB(720p・h264_mf) |
| ffmpeg の展開と照合(初回、STORED の zip) | 0.25 秒。2回目以降の照合だけ 0.3〜0.9 秒 |

- 実物の iPhone の写真・動画はこの PC に無いため、どれも合成した検体。実機の iPhone の動画(回転情報付き・縦向き)での確認が残っている(§6)。
- h264_mf(ソフトウェアの MFT)は目標ビットレートを 30% ほど超えることがある(testsrc2 で 632kbps 指定 → 824kbps)。S-8 の作り直し(0.85 倍 × 最大2回)で上限内に収まった。

## 5. テスト

- `tests/modules/sendprep/`: 80 件(うち `win32_real` 2 件: 実機の文字認識 AC-7、実物のショートカット AC-11)。
- 動画のテストは、開発用の ffmpeg の zip(`third_party/ffmpeg/`、git worktree のときは本体の作業フォルダの `third_party/ffmpeg/` も探す。`DESKKIT_TEST_FFMPEG_ZIP` でも指定可)から同梱と同じ形の zip を一時フォルダに作る。無ければ skip。
- HEIC の検体(AC-6)は pi-heif が書き出せないため、kvazaar で作った HEVC の1枚を HEIF の箱に手で入れた 1.4KB のファイルを base64 でテストに埋め込んだ(Make と GPS の Exif アイテム付き)。

## 6. 実機で確かめてほしいこと

- 実物の iPhone の HEIC(10bit・深度/ゲインマップ付き)と、縦向きの HEVC・MOV(回転情報付き)。縮小の式は回転後の短辺で 720/480 にしている。
- h264_mf が無い PC(N エディションなど)での VQ-2 の表示。
- エクスプローラーの「送る」→ DeskKit が起動していないときの起動と転送(本体の H-B)。
- 「出力をまとめてコピー」を Discord・エクスプローラーに貼り付けられること(`CF_HDROP` + `Preferred DropEffect`)。
- 高 DPI(150%・200%)での伏せ字エディタの操作。
