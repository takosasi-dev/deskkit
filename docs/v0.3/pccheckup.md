# PcCheckup v0.3.0 — 仕様書からの変更点と実測値

対象: `deskkit/modules/pccheckup/**`。仕様書(PcCheckup 実装仕様書 v1)・v0.3 共通仕様書・`docs/MODULE_GUIDE.md` からの差分と、§8 の実測値だけを書く。
逸脱不可要件(INV-1〜4・VINV-1〜5)は変えていない。しきい値(§6.2〜6.4)も表のとおり(Q-2 は未回答のまま)。

## 1. ファイル構成(§2 からの追加)

| ファイル | 役割 |
|---|---|
| `_win32.py` | ctypes の読み取り(GetAdaptersAddresses・SHQueryRecycleBinW・GetSystemPowerStatus・PowerGetEffectiveOverlayScheme・既知フォルダ・ドライブの空き)。MODULE_GUIDE §1 の「Win32 は `_win32.py` に」に合わせて probes.py から分けた |
| `fswalk.py` | リパースポイントをたどらないフォルダの走査(S3・S4・S5 と掃除で共用) |
| `runner.py` | カテゴリごとのチェックの一覧と、FR-5(例外は unknown)・FR-2(中止)の実行 |
| `fakes.py` | テストと自己検査で使う偽の Probes |

## 2. 変更点・解釈

| # | 内容 | 理由 |
|---|---|---|
| D-1 | P1・P2 の上位 5 件は **exe 名ごとに合計**して出す(chrome.exe の多数のプロセスを1行にまとめる) | 仕様書 §1 の例「chrome.exe(3.1GB)」はブラウザ全体の量のため |
| D-2 | P1 のプロセスごとの CPU は、全体の 5 秒の測定と同じ区間の平均(開始時と終了時の CPU 時間の差)を論理コア数で割る | P-3 と同じ区間で比べるため。1 秒ごとに全プロセスを読むと重い |
| D-3 | 「中止」は、CPU の 5 秒の測定中なら 1 秒以内に抜け、それまでの平均で P1 を出す。その先のチェックは行わない | FR-2 の「次のチェックから先を行わない」を守りつつ、最大 5 秒待たせないため |
| D-4 | 診断中は 3 つのボタンと「まとめて診断」を **すべて** 無効にする(同じカテゴリだけでなく) | CPU の測定中に別の診断が走ると、PcCheckup 自身が CPU を使って結果を狂わせるため |
| D-5 | GB は 1024³(Windows のエクスプローラーの表示と同じ)。P3/S1 の 5GB・15GB、S2 の 1GB、S3 の 1GB/100MB、S4 の 10GB も同じ単位 | 画面の数値をエクスプローラーと一致させるため |
| D-6 | P5 は HKCU・HKLM の Run に加えて **HKLM の WOW6432Node\…\Run(32 ビットのアプリ。StartupApproved\Run32)** と、ユーザー・全員のスタートアップフォルダ(desktop.ini は除く)を数える。ストアアプリのスタートアップ(設定アプリには出る)は数えない | Run32 は設定アプリの一覧にも出る。ストアアプリの有効/無効は管理者権限なしで確実に読む方法が無い(VINV-5) |
| D-7 | P6: 「最適な電力効率」は電源モードの GUID `961cc777-2547-4f9d-8174-7d86181b8a7a` で判定する。バッテリー駆動だけでは注意にしない(value に「バッテリー駆動(62%)」と出す)。電源モードを読めないときは good のまま「電源モードは読めませんでした」と添える | 仕様の判定表どおり。GUID は【推測】(§4 を参照) |
| D-8 | N1: プロファイルがあっても接続レベルが None なら「どこにもつながっていません」(bad) | どちらも利用者にとっては同じ状態のため |
| D-9 | N2: IPv4 が **すべて** 169.254.x.x のときだけ bad(本物のアドレスがあれば問題なし)。使えるアダプタが1つも無ければ bad「使えるネットワークの接続がありません」。value に IPv4 アドレス(LAN 内)を出す | 仕様に無いケースの補い |
| D-10 | N3: インターネット接続が無ければ info「つながっていないため、電波は調べていません」。電波とリンク速度が両方読めなければ unknown。winrt のリンク速度が 0 なら GetAdaptersAddresses の受信リンク速度を使う。WWAN(モバイル回線)も電波で判定する | 仕様に無いケースの補い |
| D-11 | N4: 料金の種類が Unknown なら unknown、接続が無ければ info。Unrestricted は good | 同上 |
| D-12 | S3 は 3 秒、S4 は 4 秒で走査を打ち切り、「(途中まで)」と付ける | FR-8「容量は S5 を除いて 10 秒以内」を、フォルダが巨大な PC でも守るため |
| D-13 | 「古い一時ファイルをごみ箱へ」を押すと、その時点でもう一度一覧を作る(最大 60 秒)。送る直前にも1件ずつ「%TEMP% の下・途中にリンクが無い・本体がリンクでない・7 日を超えた」を確かめ、外れたものは送らない(送れなかった数に入れる)。recycle は 20 件ずつ呼ぶ | 診断から時間がたつと中身が変わるため。INV-4 を二重に守る。終了時に「recycle の呼び出しが終わるまで待つ」(§10)を短くするため |
| D-14 | 掃除の対象はファイルだけ。空になったフォルダは残す | P-6 の「ファイルだけを対象」の文字どおり |
| D-15 | S4・S5 の合計には、クラウドにだけあるファイル(OneDrive のオンライン専用など。オフライン・再呼び出し属性)を入れない | ディスクを使っていないため。入れると「容量を使っている」と誤解させる |
| D-16 | S5 はユーザーフォルダ直下の **フォルダ** だけ(直下のファイルは数えない)。60 秒を過ぎたら、まだ調べていないフォルダは 0 で「途中まで」と付ける | 仕様どおり。途中の分を明示するため |
| D-17 | FR-7 の「前回より悪化」は、今回が warn / bad で、前回より重い(good < info < warn < bad)ときだけ付ける。unknown は前回・今回とも比べない | info(参考)に「悪化」を付けると不安をあおるため。読めなかったものは比べられない |
| D-18 | 中止したカテゴリは history.jsonl に書かない(まとめて診断の途中で中止したら、終わったカテゴリだけ書く) | 途中までの結果を次回の比較(FR-7)と usage に混ぜないため |
| D-19 | usage の「診断」は history.jsonl の行数(カテゴリごと)。まとめて診断は 3 回と数える。履歴は最新 200 行なので、90 日で 200 回を超えると古い日が欠ける | P-5 の履歴だけから数える(ops.jsonl には診断を書かない仕様のため)。R-2 の「0 回か」の判定には影響しない |
| D-20 | 見張り(FR-11)の最初の読み取りは、起動から最短 60 秒後。前回読んだ時刻を `watch.json`(時刻と、status ごとの最後の通知時刻だけ)に残し、再起動しても「6 時間ごと」「同じ status は 24 時間に 1 回」を守る。warn → bad のように status が変われば 24 時間以内でも通知する。通知の level は warn | PC を毎日シャットダウンする人でも 6 時間ごとに読めるようにするため。起動を遅くしないため |
| D-21 | 「結果をコピー」: ユーザーフォルダのパスを %USERPROFILE%、残ったユーザー名(2 文字以上)を %USERNAME%、コンピューター名を「(PC 名)」、N1 で読めた SSID を「(伏せ字)」に置き換える(大文字小文字を区別しない)。SSID はこの伏せ字のためだけにメモリに持ち、画面・ログ・履歴には出さない | P-4。フォルダ名などに名前が紛れても漏らさないため |
| D-22 | 設定 `watch_disk` が bool でなければ既定値(false)に戻して書き戻す(例外で停止させない) | 利用者が手で壊しても診断は使えるようにするため |
| D-23 | `handle_cli` は `(2, "unsupported")` のまま | 仕様に CLI が無いため |
| D-24 | 通知・画面の見出しの文言は仕様書の例に合わせつつ、短い文に分けた(例: N1 の LocalAccess は見出し「インターネットに出られません」、本文「ルーターまではつながっていますが、…」) | 共通 §0「1文を短くする」 |

### diagnostics() のキー(FR-15)

`watch_disk`・`running`・`last_category`(今回の起動で診断していればそのカテゴリ、していなければ履歴の最後の行。無ければ `none`)・`last_good` / `last_warn` / `last_bad` / `last_info` / `last_unknown`(件数)・`unknown_checks`(読めなかったチェック ID、無ければ `none`)。

### ログに書くもの(INV-3)

チェック ID・status ごとの件数・所要時間・例外の **型名**・件数・バイト数・理由コードだけ。例外の文(パスを含みうる)は書かない。テスト `test_ac5_no_names_in_history_ops_logs_diagnostics` で、プロセス名・SSID・ユーザー名・パスが history.jsonl・ops.jsonl・ログ・diagnostics に無いことを確かめている。

## 3. §8 の実測(2026-09-25、この PC: Windows 11 Pro 10.0.26200・論理 16 コア・メモリ 15.6GB・Wi-Fi 接続)

### 3.1 所要時間と結果(AC-6。本物の probes、ソース実行)

| カテゴリ | 所要時間 | 上限(FR-8) | 結果(status だけ) |
|---|---|---|---|
| 重い | 7.0 秒(P1 の結果が 6.4 秒、残りは 0.7 秒以内) | 10 秒 | P1 good・P2 good・P3 good・P4 good・P5 good・P6 good・P7 **warn**(更新の再起動待ち) |
| ネット | 0.42 秒 | 5 秒 | N1 good・N2 good・N3 good・N4 good・N5 good |
| 容量 | S5 以外 0.45 秒・S5 を含めて 9.7 秒 | S5 以外 10 秒・S5 60 秒 | S1 good・S2 good・S6 good・S3 good・S4 good・S5 info |

`pytest -m win32_real tests/modules/pccheckup` の 4 件(上の時間の検査と、GetAdaptersAddresses・電源・ごみ箱・ドライブ・既知フォルダの読み取り)も合格。
psutil によるプロセスの列挙は約 0.6 秒(325 プロセス)。`memory_info().private` は一般ユーザーでも全プロセスで読めた(AccessDenied 0 件)。

### 3.2 StartupApproved の値の実物(名前は伏せる)

| キー | 先頭バイト(件数) |
|---|---|
| HKCU\…\StartupApproved\Run | `02`(3 件)・`03`(5 件) |
| HKCU\…\StartupApproved\StartupFolder | `03`(1 件) |
| HKLM\…\StartupApproved\Run | `02`(1 件)・`06`(1 件) |
| HKLM\…\StartupApproved\Run32 | `02`(2 件)・`03`(4 件) |
| HKLM\…\StartupApproved\StartupFolder | `04`(1 件) |

- 値は 12 バイト(先頭 4 バイトが状態、残り 8 バイトが FILETIME。`02`/`04`/`06` の行は時刻が 0、`03` の行はほとんどが時刻あり=無効にした時刻と見られる。`03` で時刻 0 の行も 1 件あった)。先頭が偶数(02・04・06)を有効、奇数(03)を無効として数えた結果、この PC の P5 は「有効 6 個」。
- StartupApproved には、Run に値が無い(アンインストール済みの)名前も残っていた。P5 は Run・フォルダに実在する項目だけを数える。
- **要実機確認**: 設定アプリの「アプリ > スタートアップ」のオン/オフとの突き合わせは、画面を目で見る必要があるため未確認(この作業環境からは設定アプリを操作していない)。`06` と `04` が「有効」に見えるかを確かめてほしい。

## 4. 推測のまま残っているもの

- 電源モード「最適な電力効率」の GUID(`961cc777-…`)。この PC は「最適なパフォーマンス」(`ded574b5-…`)だった。設定で「最適な電力効率」に切り替えて P6 が注意になるかを確かめてほしい。
- バッテリー節約機能(省エネ機能)の判定は `GetSystemPowerStatus` の `SystemStatusFlag` の 1。この PC(バッテリーあり・AC 接続・残量 100%)では節約機能オンの状態は試していない。

## 5. 見た目の確認

- `DESKKIT_THEME=dark` / `light` で `tools/screenshot.py` を使ってページを撮り、崩れが無いことを確認した。結果カード(全カテゴリ・悪い順・問題なしの折りたたみ・一覧・次にやること・進み具合)は、偽の probes で結果を入れた画面を別に撮って両テーマ・幅 1000 と 820 で確認した。
- 横幅: `create_page()` の `minimumSizeHint().width()` は 68、中身(`widget()`)は 64(どちらも 900 以下。テスト `test_page_*_width` で、結果を入れた状態も確かめている)。
- ライトテーマの PcCheckup のアクセント色は、本体担当(H-C)が `theme.py` に足すまで catalog の色(#FB923C)のまま表示される。
- `tools/screenshot.py` は画像を保存したあと終了せずに止まる(モジュールを1つも有効にしない場合も同じ。本体側の道具の問題で、PcCheckup とは関係ない)。
