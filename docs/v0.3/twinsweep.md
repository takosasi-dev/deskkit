# TwinSweep v0.3.0 — 仕様書からの変更点と実測値

対象: `deskkit/modules/twinsweep/**`。仕様書(TwinSweep 実装仕様書 v1)・共通仕様書(v0.3)・`docs/MODULE_GUIDE.md` からの差分と、§8 の実測値だけを書く。
逸脱不可要件(INV-1〜5・VINV-1〜5)は変えていない。設定(§9)・キャッシュのスキーマ・ops.jsonl の項目も仕様書のとおり。

## 1. ファイル構成

仕様書 §2 のファイルに加えて、次の2つを置いた(機能は増やしていない)。

| ファイル | 役割 |
|---|---|
| `job.py` | 1回のスキャンの流れ(数える → 特徴 → グループ)。スキャンのスレッドで動き、キャッシュの接続もこのスレッドだけで使う |
| `results.py` | 結果の状態(グループの一覧・写真ごとの「残す」「ごみ箱へ」)。G-5・INV-2 の判定をここに集めた |

## 2. 変更点・決めたこと

| # | 内容 | 理由 |
|---|---|---|
| T-1 | ハードリンクの判定に使うファイル ID は ctypes ではなく `os.stat()` の `(st_dev, st_ino)`(Windows ではボリュームの番号とファイル番号)。完全一致の候補(大きさと SHA-256 が同じもの)にだけ読む | Python の `os.stat` が `GetFileInformationByHandle` と同じ値を返す。全ファイルに読むと遅いので候補だけにした |
| T-2 | 隠し・システム属性の **フォルダ** にも入らない(仕様書はファイルだけ) | ドライブの直下を調べると `$RECYCLE.BIN`(ごみ箱の中の写真)・`System Volume Information` を数えてしまう。選んだフォルダそのものが隠しフォルダなら調べる |
| T-3 | リパースポイントは種類で分けた。フォルダ: ジャンクション・シンボリックリンクなどはたどらない。OneDrive などのクラウドの種類(`IO_REPARSE_TAG_CLOUD*`)のフォルダだけは入る。ファイル: シンボリックリンク・マウントポイントは数えない。それ以外(圧縮(WOF)・重複除去など)は数える | OneDrive の中はフォルダもファイルもクラウドの種類のリパースポイントなので、全部を除くと OneDrive の写真を1枚も調べられない。オンラインのみのものは属性(§10)で別に飛ばす |
| T-4 | 「クラウドにだけある」の判定は `OFFLINE`・`RECALL_ON_DATA_ACCESS` に加えて `RECALL_ON_OPEN` も使う | どれも開くとダウンロードが始まる印(§3 の非スコープ) |
| T-5 | 1枚の写真が「まったく同じ写真」のグループ(の「残す」)と「似ている写真」のグループの両方に入ることがある。状態(残す/ごみ箱へ)は1つを共有し、G-5 は入っているグループ全部で確かめる。初期状態では、完全一致のグループの「残す」は似ているグループでも「残す」にする | 完全一致のコピーと縮小版が両方あるとき、縮小版をまとめるには元の写真を似ているグループにも入れる必要がある。完全一致の「残す」を似ているグループで「ごみ箱へ」にすると、完全一致のグループに「残す」が無くなる(INV-2)。そのため、似ているグループに「残す」が2枚になることがある(§5 の Q-2) |
| T-6 | 完全一致のグループで「残す」以外のコピーは、似ているグループの材料に入れない。同じ実体(ハードリンク)の2つ目以降は結果から外す | 同じ写真が3つのグループに出ないようにする(§10 のハードリンク) |
| T-7 | 読めない画像もキャッシュに残す(`dhash` を NULL にした行) | 2回目以降に壊れた画像を開き直さない(AC-8) |
| T-8 | 中止したスキャンの結果は出さない(それまでの結果があれば残す)。「中止しました。ここまでに調べた分は次回に使います。」を出す | 途中までのグループは不完全で、誤解のもとになる |
| T-9 | 「似ている度合い」「探す写真」を変えると、選択(残す/ごみ箱へ)は初期状態(G-4 の候補が「残す」)に戻る | グループが変わるため、前の選択を持ち越すと G-5 の保証が崩れる |
| T-10 | FR-13 の「スキャンのあとに変わった写真」には、消えた・読めなくなった写真も数える | どちらも送らない(送れない)ので、利用者には同じ説明で足りる |
| T-11 | ops.jsonl の `scan` 行: `bytes` は初期状態の「減らせる大きさ」、`skipped` は読めなかった枚数、`sent` は 0。`recycle` 行: `files` は送ろうとした枚数、`skipped` は送らなかった枚数(変わっていた + `recycle` が返した理由つきのもの)、`groups` は「ごみ箱へ」を含むグループの数 | 仕様書は項目だけで中身の定義が無かった |
| T-12 | FR-3 の「DeskKit のデータフォルダ」は `ctx.data_dir` の親(`%LOCALAPPDATA%\DeskKit`。テストでは `DESKKIT_HOME\local`)。設定の `%APPDATA%\DeskKit` は `%APPDATA%` に含まれる | host の内部(`deskkit.paths`)を import しないため(契約 §3) |
| T-13 | ドライブの直下の確認(「時間がかかります。続けますか」)は、フォルダを **追加するとき** に出す | スキャンを押したときに毎回聞かれるより分かりやすい。設定ファイルを手で書き換えた場合は確認なしで調べる |
| T-14 | 段階的な描画: グループは最初に 50、「さらに表示」かスクロールで 50 ずつ足す。1回のイベントループで描くのは 10 グループまで。1グループの写真は最初の 30 枚だけ並べ、「残り N 枚を表示」で 30 枚ずつ足す。サムネイルは折り返して並べる | 数千グループ・数百枚の連写でも固まらないようにする(NFR-4)。横幅を増やさない |
| T-15 | 送ったあと・並べ直したあとの一覧は、描いていた数(50 以上)まで描き直す | 送るたびに先頭に戻らないようにする |
| T-16 | `handle_cli` は `(2, "unsupported")`。トレイの状態行に「待機中」「調べています」「似た写真のグループ N」を出す | 仕様書に CLI が無い。状態行は host の既存の仕組み |
| T-17 | 画面の「おすすめ」の理由は5つ: いちばん解像度が高い / いちばん先に撮った写真 / いちばんくっきりしている / いちばんファイルが大きい / どれも同じなので最初の1枚 | G-4 の比べる順のうち、決め手になった項目を出す |
| T-21 | G-4 の比べる順を「画素数 → 撮影日時(無ければ更新日時、秒単位)が古い → 鮮明さ → 大きさ」に変えた(2026-09-25、利用者の判断。Q-2 の回答) | 明るさ・コントラストを上げた編集版は鮮明さが高く出て、元の写真より選ばれてしまうため |
| T-18 | `diagnostics()` のキー: `state` `cache_rows` `last_scan_files` `last_scan_groups` `last_scan_seconds` `last_scan_unreadable` `last_scan_status` `level` `exact_only` `recursive` `folders`(フォルダの **数**) | FR-20 の項目に、状態と設定を足した(どれも件数・値だけ) |
| T-19 | 別スレッドから画面へ返す処理(`ctx.call_soon`)と画面の操作の例外は、ログに **型名だけ** を書く | `ctx.safe` は例外の文とトレースバックをログに書く。`OSError` の文にはファイル名が入るので、INV-4 を守れない |
| T-20 | numpy と Pillow は `importlib.import_module` で読み、型は `Any` にした(`hashing.numpy()` / `hashing.pil_image()`) | numpy 2.5 の型スタブは Python 3.12 の構文(`type` 文)で書かれていて、pyproject の `python_version = "3.11"` の mypy では解析できずに止まる。Pillow の型情報も numpy を読む(§4 の契約変更の提案 P-1) |

## 3. 実測値(§8・AC-11)

測り方: `tests/modules/twinsweep/test_real_win32.py::test_ac11_2000_photos`(`pytest -m win32_real`)。検体は一時フォルダに合成し、測り終えたら消した。

- 検体: 1920×1080 の JPEG 2,000 枚(合計 457MB、1枚あたり約 230KB)。元の画像 1,600 枚と、そのうち 400 枚の複製(縮小 1280×720・再圧縮 quality 60・明るさ +10% を順に約 133 枚ずつ)。画像はなめらかな色の模様に細かい粒を足したもの。
- PC: この PC(pc1240036)、ソース実行(Python 3.13.2、ワーカー 4 本)。

| 項目 | 値 | 基準 |
|---|---|---|
| 初回のスキャン | **15.0 秒**(数える 0.02 秒・特徴 14.7 秒・グループ 0.3 秒) | 3 分以内(AC-11) |
| 2 回目のスキャン(キャッシュあり) | **0.5 秒**(特徴 0.3 秒・グループ 0.2 秒) | 30 秒以内(AC-11) |

| 似ている度合い | グループ数 | 複製を見つけた割合 | 無関係な画像が混ざったグループ |
|---|---|---|---|
| 厳しめ(4) | 400 | 400 / 400(100%) | 0 |
| ふつう(8) | 400 | 400 / 400(100%) | 0 |
| ゆるめ(12) | 404 | 400 / 400(100%) | 4 |

- 合成画像は本物の写真より見分けやすい。縮小・再圧縮・明るさ +10% はどれも dHash の距離がほぼ 0〜2 で、「厳しめ」でも見つかった。「ゆるめ」では無関係な画像どうしが 4 組まとまった。
- Q-1(しきい値 4/8/12)への材料: この検体では「ふつう」の 8 で取りこぼしも混ざりも無かった。連写(構図が少しずつ動く写真)は合成していないので、実際の写真での確認が要る(§5)。

## 4. 契約変更の提案

| # | 提案 | 理由 |
|---|---|---|
| P-1 | `pyproject.toml` の `[tool.mypy] python_version` を `"3.13"`(開発環境と同じ)にする | numpy 2.5 のスタブが 3.11 の mypy で解析できない。Pillow を import するだけで mypy が止まるので、sendprep・pccheckup も同じ問題に当たるはず。直ったら T-20 の `importlib` をやめて普通に import できる |
| P-2 | theme の `_LIGHT_MODULE_ACCENTS` / `_CHART_DARK` に twinsweep の色を足す(H-C) | 今はライトでも `#A3E635`(淡い黄緑)のままで、白地の「おすすめ」の印・トグルが読みにくい。画面は `catalog.info("twinsweep").accent` を実行時に読むので、足せばそのまま効く |
| P-3 | `ctx.safe`(と `call_soon`)のログを、v0.3 のモジュールについては例外の型名だけにする、または MODULE_GUIDE に「例外の文にパスが入る処理は自分で握る」と書く | T-19。VINV-4 を host 側でも守りやすくする |
