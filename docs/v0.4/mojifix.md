# MojiFix v0.4.0 — 仕様書からの変更点と実測値

対象: `deskkit/modules/mojifix/**`。MojiFix 実装仕様書 v1(末尾の「未確定事項への回答(2026-09-28、作者)」を含む)・v0.4 共通仕様書・
`docs/MODULE_GUIDE.md`・`docs/INTERFACES_v0.4.md` からの差分と、§8 の実測値だけを書く。逸脱不可要件(INV-1〜INV-7・V4INV-1〜5)は変えていない。
本体(host)の変更には頼っていない(仕様書 §2「本体に頼むこと」は catalog と selftest の `all` だけで、どちらも main にある)。
使っているのは標準ライブラリ(`codecs`・`zipfile`・`unicodedata`・`os`・`shutil`)・PySide6・ctypes(「ドキュメント」の場所だけ)。

## 1. ファイル構成(§2 からの追加)

| ファイル | 役割 |
|---|---|
| `config.py` | 設定(§9)の既定値と、型・範囲の合わない値の補い |
| `owned.py` | その回に自分が作ったファイル・フォルダの一覧(作った順)と後片づけ(FR-4)、出力の名前の予約(M-16) |

`os.remove` / `os.rmdir` があるのは `owned.py` の後片づけの関数(`_remove_own_file` と `Owned.discard`)だけ(AC-18。`tests/modules/mojifix/test_grep.py` で確かめている)。
`zipextract` の展開の関数は、AC-18 の grep(`\.extract\(`)に掛からないよう `unpack()` と名付けた。

## 2. 変更点・解釈

| # | 内容 | 理由 |
|---|---|---|
| F-1 | 出力の名前は **`<元の名前>_文字直し<元の拡張子>`**(例 `売上.csv` → `売上_文字直し.csv`)、同名があれば ` (2)` から 1,000 まで | Q-3 の回答(本文の `_fixed` より優先) |
| F-2 | テキストの空き容量の確かめ(「元の大きさ × 2 + 100MB」)は、1GB を超えるときだけでなく **いつも** 行う。書き出し先(同じフォルダか「ドキュメント\MojiFix」)のドライブで見る | 安全な側。小さいファイルで引っ掛かるのは空きが 100MB 未満のときだけ |
| F-3 | 候補づくり(先頭 256KB)の「読めない所」は、C の `errors="replace"` で読んで **続いた U+FFFD を1か所** と数える。確認の読み(M-5)と〓の置き換えは `codecs.register_error` の独自の処理で「読めないバイトの並び1つにつき1つ」を数える | 独自の処理を1か所ずつ呼ぶと、合わない候補は読めない所が数十万になり 256KB で 0.55 秒かかった(実測)。速い数え方では 0.04 秒。元の文字に U+FFFD があると候補の数だけ1つ多く数えるが、並べる順と「読めました」の判断にはほぼ影響しない |
| F-4 | 候補の「先頭 8 行」「先頭 40 行」は、先頭 256KB を読んだ文字列から取る。改行で終わらない最後の行も出す | FR-6・FR-7 |
| F-5 | GB は 1024³ バイト、MB は 1024² バイトで数える(`zip_max_total_gb`・M-10 の (c)(d)・FR-21 の「あと X GB」) | 決まっていなかったため |
| F-6 | FR-19 (2) の「最初の部分が `<英字>:`」は、最初の部分が `<英字>:` **で始まる** ものを飛ばす(`C:x.txt` も飛ばす)。予約名は、最初の `.` より前の部分の後ろの空白を除いてから比べる(`aux .txt` も飛ばす) | Windows はどちらもドライブ・装置として扱うため(安全な側) |
| F-7 | FR-19 に次の「飛ばす」を足した: 「同じ名前のファイルとフォルダがぶつかる」(先に出たファイルと同じ名前のフォルダの中の項目・フォルダの項目)、「同じ名前がすでにある」(展開の直前の `os.rename` が 183 のとき。ふつうは起きない)、FR-23 の「壊れていた」 | 決めた名前どうしの衝突を、上書きせずに1か所で止めるため |
| F-8 | FR-19 (7) の 260 字は、一覧を出すときは「zip と同じフォルダの `<zip の名前>`」で見積もり、展開するときは予約した実際の展開先(` (2)` の付いた名前、「ドキュメント\MojiFix」など)で作り直して当てる | 展開先は展開を始めるまで決まらないため |
| F-9 | zip 爆弾の (b)〜(d) は、飛ばす項目も含めた zip 全体で見る。空き容量(FR-21)は展開する項目だけで見る | 安全な側 |
| F-10 | 0x7075 の中身が UTF-8 として読めない zip は、`zipfile` が開く時点で `BadZipFile` を出すので「zip を読めませんでした」になる | P-8 の zipfile の振る舞い |
| F-11 | 方式 12(bzip2)・14(LZMA)は標準の `bz2`・`lzma` で展開する | FR-17 のとおり。exe に入っているかは §5 |
| F-12 | FR-12 で「Excel で開ける形に変える」を選んだら、確認の読みをやり直さずに(文字数は同じ)書き出し、設定の `text_output` も `excel` に保存する | 画面の選択を変えたら保存する(§9) |
| F-13 | 確認の読みの結果(FR-11・FR-12 の問い)のあとに続けるときは、確認をやり直さず、その結果の大きさ・更新日時で FR-15 を確かめて書く | 1GB を3回読まないため(M-5 の2回のまま) |
| F-14 | テキストの `composed` は「くっつけで消えた結合文字の数」、zip の `composed` は「くっつけた名前の数」、名前の変更の `composed` は「変えた名前の数」 | ops の形(§9)は同じで、数え方だけ決まっていなかったため |
| F-15 | ops に `refused` を書くのは: 読み込みで止めたとき(`empty`・`binary`・`unreadable`、zip の FR-17 の理由)、FR-11・FR-12 で「候補を選び直す」「やめる」を選んだとき(`undecodable`・`unencodable`)、調べられないフォルダ(`forbidden_folder`)・20 万項目超(`too_many_items`)。展開の直前に zip が変わっていたら `error` / `changed` | §9 の理由コードの範囲で |
| F-16 | 名前の変更・取り消しで1件も変えられなかったときは、ops の `result` を `error` にする(usage の「直した回数」に数えない) | R-2 の数え方をゆがめないため |
| F-17 | usage は「直した回数」(primary。text・zip・rename の `ok`)と、種類ごとの回数(text・zip・rename)を返す。diagnostics は起動からの `count.<op>.<result>`・`count.reason.<理由>`・`last_ms`・設定の値・`busy`・`text_queue`・`undo_available` | FR-31・FR-32 |
| F-18 | トレイに「MojiFix を開く」を置いた。画面に数値タイル(今日直した・積んだファイル・直せる名前)を置いた | MODULE_GUIDE §4 の定番の形(SendPrep と同じ) |
| F-19 | FR-1 の振り分けで、zip とフォルダは「最後に来た1つ」に置き換わる(テキストは 50 件まで積む)。処理中に来た物は、今の処理が終わってから読み込む。フォルダは調べる前に「調べる」を押す(ドライブの直下は確認のあと) | M-17 はテキストだけの決まりで、zip・フォルダは1つずつ扱う画面にしたため |
| F-20 | 画面の「今の名前」の強調は、分かれた文字(結合する記号・ハングルの字母)の前に「◌」を入れて色を付ける | 濁点は前の字に重なって見えるため、目印が要る |
| F-21 | `%LOCALAPPDATA%` の中は調べない(FR-25)ので、`%TEMP%`(ふつう `%LOCALAPPDATA%\Temp`)も「このフォルダは調べられません」になる | 仕様書のとおり。気づきとして書いた |

## 3. 決めた既定値

§9 のまま(`text_output=excel`・`newline=keep`・`text_compose=false`・`zip_compose=true`・`zip_skip_mac_files=true`・`zip_max_total_gb=20`・`rename_recursive=true`)。

## 4. 実測(2026-09-28、この PC・ソース実行・Python 3.13.2)

| 項目 | 値 |
|---|---|
| 候補づくり(先頭 256KB・6 候補) | 0.04 秒(F-3 の前は 0.55 秒) |
| 1GB の Shift_JIS の CSV(合成、LF 1,628 万行)を「Excel で開ける形・CRLF」 | 確認 40.8 秒、書き出しと読み直し 36.1 秒、出力 1,537MiB。作業セットの増え方の山は 10MiB |
| 10,000 件・1.91GiB の zip(無圧縮、UTF-8 の印あり)の展開 | 読み込み 0.46 秒・一覧 0.21 秒・展開 46.3 秒(約 42MB/s)。作業セットの増え方の山は 25MiB |
| `NFC` で別の1字に置き換わる字の数(M-13 の集合) | 1,035 字(P-12 と一致)。初めて使うときに 0.6 秒で作る(ワーカーの中) |

計測は `scratchpad` の一時フォルダで行い、検体は消した。エクスプローラーとの比較はしていない(§5)。

## 5. 実機で確かめること

- エクスプローラーの「すべて展開」で同じ 10,000 件・2GB の zip を展開した時間(§8 の比較)。
- macOS の「圧縮」・Windows 11 のエクスプローラーの圧縮・7-Zip の既定で作った日本語名の zip の、ビット 11 の有無と名前の形(NFD か)と、MojiFix の候補の1番目。
- インターネットから落とした zip で、エクスプローラーの展開が各ファイルに `Zone.Identifier` を付けること(M-11 の前提)。MojiFix が同じ中身を付けること
  は `test_ac13_zone_identifier`(`win32_real`、NTFS の一時フォルダ)で確かめた。FAT32・exFAT の USB メモリへ展開して「印を付けられませんでした」が1回出ること。
- M-2 の並べ方を手元の実物(Excel で保存した CSV、Mac の Numbers の CSV、古いメールの本文)で試した結果。
- exe で bzip2(方式 12)・LZMA(方式 14)の zip を展開できること(`bz2`・`lzma` が exe に入っていること。F-11)。
- ほかのソフトで開いているファイルの名前を直すと「ほかのソフトが使っています」が出ること(FR-29)、OneDrive のフォルダで直したときの同期。
- 画面の見た目は offscreen で描いて確かめた(ライト・ダーク)。本物の Control Center での表示(日本語の太字の字形の置き換え)は未確認。
