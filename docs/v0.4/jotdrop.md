# JotDrop v0.4.0 — 仕様書からの変更点・既定値・実測値

対象: `deskkit/modules/jotdrop/**`。仕様書は `JotDrop_どこでも一行メモ_仕様書.md`(J-* / FR-* / INV-* / AC-*)。
逸脱不可要件(INV-1〜7・V4INV-1〜5)は変えていない。設定の既定値は仕様書 §9 のまま(ホットキーは未割り当て)。

## 1. ファイル

仕様書 §2 のとおり(`compose` / `target` / `writer` / `pending` / `oplog` / `_win32` / `popup` / `page` / `module` / `selftest`)。
テストと自己検査のために `fakes.py`(メモリの中にファイルを持つ偽の `Win32Api`。開いたときの権限・共有・作り方を記録する)を足した。

- 登録名は `jotdrop.open_input`(`ctx.hotkeys.register_text("jotdrop.open_input", hotkey)`)。ホームでの表示名(H4-7)は本体担当。
- 追記のハンドルの権限は `FILE_READ_DATA | FILE_APPEND_DATA | FILE_READ_ATTRIBUTES | SYNCHRONIZE`、共有は `FILE_SHARE_READ`(INV-1。`_win32.APPEND_ACCESS`)。
  取り消しだけは別のハンドルを `FILE_READ_DATA | FILE_WRITE_DATA | …`・共有 0 で開く(`SetEndOfFile` に `FILE_WRITE_DATA` が要るため)。切り詰めるのは J-18 の条件がそろったときだけ。
- フォルダを作るのは既定の「ドキュメント\JotDrop」だけ(`CreateDirectoryW` を1回。J-16)。

## 2. 仕様書からの変更点・解釈

| # | 内容 | 理由 |
|---|---|---|
| JD-1 | 入力欄の窓は `start()` の中ではなく、**start() の 3 秒後**(`POPUP_PREBUILD_MS`)に作って隠しておく。それより前にキーが押されたら、その場で作って出す | 初めて作るときに Qt の字形・部品の準備で約 1 秒(冷えた状態では 5 秒)かかった(§3)。start() で作ると DeskKit の起動が遅れる(NFR4-2 の 0.5 秒)。J-2 の「押してから打てるまでを短く」は、前もって作ることで守れている |
| JD-2 | 預かったメモ(pending.jsonl)は仕様書 §9 の形(`id` / `created` / `path` / `line` / `reason`)だけを持つ。書き直すときの空行・区切り・改行の形・ヘッダーは、**書き直すときの設定**を使う | §9 の形に組み方の設定が無い。1行と書き込み先は Enter の瞬間のまま |
| JD-3 | 預かりの理由コードを2つ足した: `no_file`(`create_file` が偽でファイルが無い)・`bad_target`(拡張子が .md / .txt でない。設定の検証をすり抜けたとき)。どちらも自動では書き直さない | §9 の理由の一覧に当てはまる物が無かった |
| JD-4 | 空のファイル(0 バイト)と、ヘッダーの無い新しいファイルには、空行も区切りも入れない(1行目にそのまま書く) | J-12 の「末尾が空行でなければ空行」を字のとおりに行うと、ファイルの先頭が空行になる |
| JD-5 | `new_file_header` で使える変数は `{date}` だけ(`{time}` `{text}` は保存しない) | FR-10 が「`{date}` を展開」とだけ書いている |
| JD-6 | 照合(J-19)は、自動・手での書き直しで書けたメモにも 10 秒後に行う | 書き直しも「書いた」ことに変わりはないため |
| JD-7 | 自動の書き直し(FR-12)は、ホットキーのときも一時停止中は行わない | 書き直し自体は自動の処理のため(手の「もう一度書く」は一時停止中でも書く) |
| JD-8 | クイックアクションは足していない。トレイの3項目(「メモを書く」「直前のメモを取り消す」「書き込み先を開く」)が自動で候補に入るため(MODULE_GUIDE §3) | FR-15・FR-18 の入口はトレイ項目で足りる |
| JD-9 | トレイ・クイックアクションから取り消したときは、取り消した本文を入れた入力欄を出す(元の窓は覚えていないので戻さない) | FR-15「取り消した本文は入力欄に戻す」を、入力欄が閉じているときにも満たすため |
| JD-10 | `target_confirmed` の既定が false なので、**最初の1回**(既定の書き込み先のままでも)は J-17 の確かめが出る | 仕様書 §9 の既定値どおり。書いたことの無い場所に黙って書かないため |
| JD-11 | 設定の値が型・範囲・書式に合わなければ(手で壊した settings.json など)、その値だけ既定値に戻して書き戻す(例外で止めない)。ホットキーは値を消さない(J-1) | MODULE_GUIDE §2 |
| JD-12 | `ops.jsonl` の `reason` には、預かりの理由コードのほか、取り消しを断った理由(`busy` / `changed` / `failed`)を書く | §9 の `undo_refused` の理由を区別するため(本文・パスは入らない) |
| JD-13 | 「書き込み先を開く」は、今日のファイルがあれば `os.startfile` で既定のアプリ、無ければフォルダを開く。フォルダも無ければ知らせるだけ | FR-18 |
| JD-14 | 入力欄の空のときの Ctrl+Z は、IME の変換中は取り消しに使わない | 変換中の Ctrl+Z を IME に渡すため |

### diagnostics() のキー(FR-22)

`hotkey_set`・`hotkey_registered`・`target_default`(フォルダが既定か)・`pattern_has_date`・`format`(`bullet` / `heading` / `custom`)・
`target_confirmed`・`pending`(件数)・`last_result`(`sent` / `retry_ok` / 理由コード / `none`)・`blocked`(この起動で出さなかった回数)。

### ログ・操作記録に書くもの(INV-3・J-15)

結果コード・理由コード・再試行の回数・所要時間・件数・例外の型名だけ。本文とパスとファイル名は書かない(pending.jsonl だけが持つ)。
テスト `test_ac15_no_secret_text_or_path` で「ひみつXYZ」と「PATHMARK」が、ログ・ops.jsonl・diagnostics・usage・通知・トレイの状態・窓の題に無いことを確かめている。

## 3. 実測(2026-09-28、この PC: Windows 11 Pro 10.0.26200。ソース実行)

### NFR4-5: 入力欄に文字を打てる状態になるまで(300ms 以内)

キーは送らず、ホットキーの処理(`on_hotkey()`)を直接呼んで、自分の入力欄が「見えて・入力にフォーカスがある」までと、OS の前面の窓(`GetForegroundWindow`)が
入力欄になるまでを測った。閉じるたびに元の前面の窓へ戻した(J-4 と同じ)。20 回:

| 項目 | 結果 |
|---|---|
| 見えてフォーカスがある | 中央値 **9.6ms**・最大 37.5ms(1回目)。20/20 |
| OS の前面になった | 20/20(中央値 9.6ms) |
| 200ms 後の「ここをクリックしてから書いてください」 | 0/20(出なかった) |
| 閉じたあと元の窓へ戻った | 20/20 |

- WM_HOTKEY を受けてから `on_hotkey()` が呼ばれるまで(本体の中継)は含まない。
- この計測のプロセスは、前面にいたアプリから起動された子プロセスなので、前面になる条件を満たしていた。**ホットキーを押したことが条件に当たるか**(実際の使い方)は、実機で確かめること(§4)。

### 入力欄を作る時間(JD-1 の理由)

- 同じプロセスで Qt の部品をまだ作っていない状態で入力欄を作ると、957ms(1回目の計測では 5.4 秒)。内訳は最初の `QLineEdit` の生成 約 0.7 秒・字形のフォントの一覧 約 0.36 秒(cProfile)。
- 作ったあとの `start()` そのものは 1ms 未満。

### 本物の CreateFileW での確かめ(`pytest -m win32_real tests/modules/jotdrop`、5 件とも合格)

- `FILE_APPEND_DATA` だけのハンドルで、書く前の内容の SHA-256 が変わらず、末尾に足せた(AC-1)。取り消しで書く前と同じ SHA-256 に戻り、あとから足したファイルは取り消さなかった(AC-12)。
- **共有の実際**: 書き込みも共有して読んでいるハンドル(`FILE_SHARE_READ|WRITE|DELETE`)があっても書けた。読み取りだけを共有して開いているハンドル・共有なしのハンドルがある間は、
  5 回試して預かり(`busy`)になり、閉じると自動の書き直しで、あとから送ったメモより前に書かれた(AC-4)。

## 4. 実機で確かめること(仕様書 §8。この作業環境ではできなかったもの)

依頼者の画面で他のアプリを操作する・キーを送る必要があるため、次は行っていない。

- ホットキーで開いた入力欄がキー入力を受け取れた回数(メモ帳・Chrome・エクスプローラー・Obsidian・管理者のコマンドプロンプトから各 20 回)と、受け取れなかったときに文字が元のアプリに入ったか(R-3)。
- 閉じたあとに元の窓へ戻れた回数(同じ5つ。管理者の窓へ戻れるか)。
- 登録したキーが前面のアプリにも届くか。
- Microsoft IME(と Google 日本語入力)で、変換中の Enter で送られないか。確定の Enter が窓にも届くか、届くなら確定から何 ms 後か(J-6 の 100ms の妥当さ)。入力欄を開いたときの IME のオン・オフ(Q-5)。
  変換中・確定直後・押しっぱなしの Enter で送らないことは、偽の IME の入力(`QInputMethodEvent`)のテストで確かめた(AC-9)。
- Obsidian で同じノートを開いて打っている最中に書き、10 秒後に行が残っているか(10 回)。Obsidian が開いているだけのときに使用中になるか(§3 のとおり、読み取りだけを共有して開くアプリがいると使用中になる)。OneDrive のフォルダでも同じ。
- 「書きました」の印がフォーカスを取らないか(`WindowDoesNotAcceptFocus` と `WA_ShowWithoutActivating` を付けてある)。
- モジュールを有効にして何もしないときの作業セットの増え方(NFR4-1 は本体担当の `measurements.md`)。

## 5. 契約変更の提案

無し(`ctx.hotkeys.register_text` / `triggered` と既存の ctx だけで作った。§2.1・§2.2 の新しい API は使っていない)。

### 回答(2026-09-29、統合のとき)

- 利用者の答え: 上の「聞くこと」はすべて今の案のまま v0.4.0 に入れる。

### 統合のときの直し(2026-09-29)

- 書いて 10 秒以内に取り消すと、予約済みの照合が「見つからない」と判断して、取り消したメモを預かりに戻していた → 取り消したメモは照合しない(`test_undo_before_verify_is_not_missing`)。
- 預かり分の取り消しを GUI のスレッドで行っていて、自動の書き直しと重なると同じメモが2件になりえた → ワーカーの列で行い、先に書かれていたら取り消さずに知らせる(`test_undo_pending_after_retry_wrote_it`)。
