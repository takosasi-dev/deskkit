# PagePress v0.4.0 — 仕様書からの変更点・既定値・実測値

対象: `deskkit/modules/pagepress/**`。仕様書(PagePress 実装仕様書 v1、2026-09-28)・v0.4 共通仕様書・`docs/MODULE_GUIDE.md`・`docs/INTERFACES_v0.4.md` からの差分と、§8 の実測値を書く。
逸脱不可要件(INV-1〜INV-9・V4INV-*・VINV-*)は緩めていない。設定(§9)・ops.jsonl の項目・pending.json の形は仕様書のとおり(設定に `sendto_enabled` を1つ足した。P-16)。

## 1. ファイル構成

仕様書 §2 のファイルに加えて、次の4つを置いた。

| ファイル | 役割 |
|---|---|
| `config.py` | 設定の既定値と正規化(§9。合わない値は既定に戻す) |
| `_win32.py` | ctypes: 既知のフォルダ(ドキュメント・送る)と IShellLinkW。SendPrep の同じ部品を写した(C-1 のためモジュールをまたいで import しない) |
| `sendto.py` | エクスプローラーの「送る」への登録/解除(Q-2 の回答。SendPrep の `sendto.py` を写して `pagepress open` にした) |
| `page.py` の中の `_Tab` など | 4つのタブの共通部品(投入エリア・注意書き・実行の行・進捗・結果) |

pypdfium2 を import するのは `render.py` だけ(INV-2・AC-17)。消す処理は `naming.remove_own` の1か所だけ(AC-18)。

## 2. 変更点・決めたこと

| # | 内容 | 理由 |
|---|---|---|
| P-16 | 「送る」に「PagePress でまとめる」を足せるようにした(設定 `sendto_enabled`、既定 false。画面の「エクスプローラーから使う」のスイッチ)。リンク先は exe なら `DeskKit.exe pagepress open`、ソース実行なら `pythonw.exe run_deskkit.py pagepress open`。オフにすると自分が作ったショートカットだけを消す(同じ名前の他人のショートカットは消さない・上書きしない) | Q-2 の回答(2026-09-28、利用者)。作りは SendPrep FR-20 と同じ。ショートカットを消す処理も `naming.remove_own` を通す(AC-18 の1か所に集める) |
| P-17 | 名前付きの行き先(`/Names /Dests`)を指すリンク注釈・`/GoTo` の動作は、書く前にページの参照に直す。行き先のページが出力に無ければ、そのリンクを外す(`sanitize.resolve_named`) | §8 の実測: pypdf の `append` はしおりの名前付きの行き先はページの参照に直すが、**リンク注釈の `/Dest`(名前)はそのまま**運ぶ。P-5 で `/Names` を捨てると飛べなくなるため |
| P-18 | 抜いたページを指すリンク(明示の行き先)は、pypdf の `append(pages=...)` が外す(§8 の実測)。念のため掃除でも、出力に無いページ・名前だけの行き先を指すリンクと、行き先も動作も無いリンク(禁止の動作を外した結果)を注釈ごと外す | AC-2(`/URI` のリンクだけが残る) |
| P-19 | P-5 に加えて、文書の `/AA`(閉じるときなどの動作)と古い形の名前付きの行き先 `/Dests` も持ち込まない。FR-19 の検査は、ページ・注釈・しおり・入力欄の木を辿り(中身の `/Resources`・`/Contents`・`/AP` は読まない)、`/AA`・`/JS`・禁止の動作(`/S`)・禁止の注釈(`/Subtype`)・埋め込みファイル(`/EmbeddedFile`・`/EF`)・ページの `/PieceInfo` `/Metadata`、文書の `/Names` `/OpenAction` `/Metadata` `/PageLabels` `/AA`、`/AcroForm /XFA`、trailer の `/Info` `/Encrypt` を1つでも見つけたら落とす | 安全な側。中身まで読むと 500MB の画像を全部メモリに持つので、動作を置ける場所だけを辿る |
| P-20 | 中止の区切りは「入力ごと(PDF の `append` は1つずつ)・画像のページごと・分けるの出力ごと・軽くするの画像ごと・整理は 50 ページごと」と、書き出しの包み(書くたびに印を見る)。1つの `append` が 1 秒で戻らないときは FR-15 どおり「中止しています」を出す | pypdf の `append` はファイル単位でしか区切れない(ページごとに `append` するとしおりの取り込みが崩れる)。2,000 ページの `append` は 0.3 秒程度 |
| P-21 | 分けるを中止・失敗したとき、その入力の途中までの出力と空の `<名前>_分割` フォルダは消す(それより前に終わった入力の出力は残す) | 「中止しました」の入力に半端なフォルダを残さない。消すのは自分の出力だけ(INV-8) |
| P-22 | 上限 200 件は「まとめる」だけでなく「分ける」「軽くする」の一覧にも当てた(文は「一度に扱えるのは 200 件までです」)。1GB は「まとめる」は合計、「分ける」「軽くする」「整理」は 1 ファイルごと(「1GB を超える PDF は扱えません」) | 安全な側。pypdf は書き出すときに中身をメモリに持つ(§3 の実測で 500MB の入力に 540〜780MB) |
| P-23 | 「ページの整理」で保存していない変更があるとき、**別の PDF を開く・タブを移る・閉じる**では確かめる。Control Center の画面を閉じたとき(ページが消えたとき)は確かめない。代わりに整理の状態(並び・回転・取り消し)をモジュールのメモリに持ち、画面を開き直すと続きから出る。DeskKit を終了する・モジュールを止めると捨てる | host の画面の切り替え・閉じる操作を止める口が無い(MODULE_GUIDE §3)。確かめずに捨てるより、残しておく方が安全 |
| P-24 | 保存の途中で並びを変えたときは、保存が済んでも「保存していない変更」のまま(保存した並びを覚えておき、それと比べる) | 保存した物と画面が違うのに「変更なし」と出さない |
| P-25 | 入力の確認(FR-2)もジョブのスレッドで1件ずつ行う。実行中に足した入力は、今のジョブが終わってから確かめる(投入エリアの下に「確かめています…(N 件)」) | 仕様書 §2 の jobs.py(入力の確認を含む)どおり、PDF を読むスレッドを1本にした |
| P-26 | 軽くするの入れ替えは、pypdf の `ImageFile.replace` ではなく、書き出し側の画像のストリームをその場で JPEG に置き換える(`StreamObject.set_data` と `/Filter /DCTDecode`・`/Width`・`/Height`・`/ColorSpace`)。対象外に `/Decode` と `/SMaskInData` を持つ画像、CMYK の DCT、2 つ以上のフィルタを重ねた画像も足した。ICCBased の画像は元の色空間のまま、Indexed は基の色空間(RGB/グレー)にする。元の大きさは `/Length`(無ければ pypdf の内部の `_data`)で比べる | `replace` は Pillow の PDF 保存を通して読み直すので2回デコードする。`EncodedStreamObject.set_data` は Flate しか受けない。色が変わる物・判定があいまいな物は触らない(P-10 の趣旨) |
| P-27 | JPEG の「作り直さない」は、モードが RGB かグレーで Orientation が 1・3・6・8(か無し)の物。2・4・5・7 と CMYK・HEIC は Pillow で向きを直して品質 92 の JPEG(CMYK は RGB にする)。PNG の 16 ビットのグレーは numpy で 8 ビットにし、パレット・グレー+透明・RGBA は白で埋めて RGB にする | P-8 の具体化 |
| P-28 | 「画像の大きさのまま」の dpi は Pillow の `info["dpi"]`(JFIF の密度か EXIF)。JFIF が縦横比だけ(単位 0)のときは記録なしとみなして 96dpi | P-9 の具体化 |
| P-29 | 行のサムネイル(一覧)は長辺 96px、整理の格子は長辺 160px。どちらも1つの LRU(300 枚)に入る | P-13 の 300 枚を全体の上限にした |
| P-30 | 軽くするの結果(FR-10)は、一覧の下の結果の行に「元の名前」と「12.3MB → 3.1MB(75% 減)」を並べて出す(一覧の行そのものは書き換えない) | 一覧は投入順のまま操作できるようにし、結果は結果の場所にまとめた |
| P-31 | 整理の格子の並べ替えは、自分で書いた drop の処理(`OrganizeView.dropEvent`)で行う。取り消しは並び全体の写しを 100 手まで持つ | QListView の IconMode は、標準の内部移動だと位置だけが動いてモデルの順が変わらない |
| P-32 | pypdf の内部の `PdfWriter._add_object` を使う(画像のページを組むときに画像と中身のストリームを間接オブジェクトにする)。pypdf 7 で変わるおそれがあるので、pyproject に `<7` を付けてほしい(§6) | 公開の API に同じことをする物が無い |

## 3. 実測値(§8)

測り方: `tests/modules/pagepress/test_measure_real.py`(`pytest -m win32_real -s`)。検体はテストの中で作った(利用者のファイルは使っていない)。
1つの操作ごとに子プロセス(`tests/modules/pagepress/measure_ops.py`)で本番と同じ部品(`jobs.run`)を動かし、そのプロセスの作業セットの最大値(psutil の `peak_wset`)を測った。
DeskKit 全体(Qt・常駐の分)は含まない。PC: この PC(pc1240036、16 コア・16GB、空きメモリ約 3.3GB)、ソース実行(Python 3.13・pypdf 6.19.0・pypdfium2 5.13.0 / PDFium 153.0.7999.0)。

- 検体 A: 文字を1つ描いた A4 のページ 2,000 枚(753KB)
- 検体 B: 2480×3508 の JPEG(品質 90、ノイズの画像で 1 枚 約 6.3MB)を A4 に1枚ずつ置いた 80 ページ(504MB)

| 操作 | 所要時間 | 作業セットの最大 | 結果 |
|---|---|---|---|
| 確認(A) | 0.35 秒 | 42MB | 2,000 ページ |
| 確認(B) | 1.78 秒 | 34MB | 80 ページ |
| まとめる(A+B、2,080 ページ・505MB) | 5.7 秒 | **574MB** | 505.0MB |
| 1ページずつ分ける(A) | 63.0 秒 | 52MB | 2,000 個(1 個 約 31ms。書く・開き直して検査・fsync・名前を変える) |
| 1ページずつ分ける(B) | 3.3 秒 | 539MB | 80 個 |
| 軽くする「ふつう」(A) | 1.1 秒 | 69MB | 753KB → 660KB(12% 減。可逆の処理だけ) |
| 軽くする「少し」(B) | 23.5 秒 | **782MB** | 504.2MB → 155.0MB(69% 減) |
| 軽くする「ふつう」(B) | 17.9 秒 | 680MB | 504.2MB → 60.8MB(87% 減) |
| 軽くする「うんと」(B) | 14.3 秒 | 629MB | 504.2MB → 14.4MB(97% 減) |

- **FR-12(AC-21 の材料)**: 検体 A を整理で開くと、確認と開くまで 0.23 秒、開いてから見えている 25 ページが揃うまで **0.25 秒**(合計 0.48 秒)。その間の GUI スレッドの最大の止まりは **38ms**(10ms ごとの心拍の最大の間)。
  offscreen の Qt(1100×900 の画面)で測った。実機の画面での確認は §5。
- **Q-1(軽くするの段階)の材料**: 文字(8〜14pt 相当の日本語)を撮った 2480×3508 の JPEG 1 ページ(1.02MB)を軽くすると、少し 478KB / ふつう 268KB / うんと 126KB。
  100% 表示(96dpi)ではどの段階も 8pt 相当まで読める。200% に拡大すると「うんと」(100dpi)は文字の輪郭がにじみ、JPEG のノイズが見える(読めなくはない)。「ふつう」は 200% でも輪郭がきれい。
  画像は測ったときの一時フォルダに `readability_<段階>_100pct.png` / `_200pct.png` として出る(リポジトリには入れない)。
- **Q-6(上限)の材料**: 505MB の入力で 540〜780MB。上限の 1GB ではおよそ 1.1〜1.6GB になる見込み。空きメモリが少ない PC(8GB 機など)では、1GB 近い入力で遅くなる・止まるおそれがある。
- **名前付きの行き先**(§8): pypdf の `append` は、しおりの名前付きの行き先はページの参照に直すが、リンク注釈の `/Dest`(名前)は直さず、`/Names /Dests` も運ぶ。P-5 で `/Names` を捨てると飛べなくなるので、P-17 を足した(テスト: `test_merge_ac1` の最後)。
- **抜いたページを指すリンク**(§8): pypdf の `append(pages=...)` が注釈ごと外す(テスト: `test_organize_keeps_only_uri_ac2` の後半)。念のため掃除でも外す(P-18)。
- **iPhone の縦持ちの HEIC**(§8): pi-heif 1.4 は開くときに回転を当て、EXIF の Orientation を 1 に戻す(`pi_heif/as_plugin.py` の `set_orientation`)。そのあとの `ImageOps.exif_transpose` は何もしないので二重に回らない、とソースから読める。
  pi-heif は書き出しができず HEIC の検体を作れないので、実物での確認は §5。
- **pdfium.dll による exe の大きさ**(§8): `pdfium.dll` は 7,260,672 バイト(zlib の最大圧縮で 3,608,303 バイト)。pypdf の .py は合計 1.7MB、pypdfium2 は 0.17MB + `bindings.py` 0.15MB。
  onefile の圧縮後で **約 4〜5MB 増える見込み**(v0.3.0 の約 98MB → 約 103MB。NFR-3 の 150MB に収まる)。ビルドしての実測は統合担当(H4-13)。

## 5. 実機で確かめること

- AC-21(FR-12): 実際の画面で、検体 A(白紙に近い 2,000 ページ)を「ページの整理」で開き、見えている分が 2 秒以内に揃うか。スクロールしても画面が固まらないか。offscreen では 0.25 秒・最大の止まり 38ms。
- 整理の格子のマウス操作: ドラッグでの並べ替え(落とした位置の左右で前後が決まる)、Ctrl・Shift での複数選択、Delete / Ctrl+Z / Ctrl+Y。offscreen ではキーの処理と移動の関数だけを確かめた。
- まとめるの一覧のドラッグでの並べ替え(QListWidget の内部移動)。
- エクスプローラーからのドロップ(ファイル・フォルダ)と「ファイルを選ぶ」。
- iPhone で縦に持って撮った HEIC を「まとめる」に入れて、縦のページになるか(§3)。
- 「送る」: スイッチをオンにして、ファイルを右クリック →「送る」→「PagePress でまとめる」で、まとめるの一覧に入るか(exe と、ソース実行の `pythonw.exe run_deskkit.py pagepress open`)。オフで消えるか。
- 「開く」(既定の PDF のアプリで開く)・「フォルダを開く」。
- 書けない場所(書き込み禁止の USB メモリ・CD など)の PDF で、`ドキュメント\PagePress\` に保存され、行に保存先が出るか。
- 空きの少ないドライブで「空き容量が足りません(あと N MB 要ります)」が出るか。
- exe の中で `DeskKit.exe --selftest pagepress` が 0 になるか(pdfium.dll が入っているか。自己検査の最後の2つが PDFium の描画)。
- 暗号化された PDF(パスワード付き・印刷の制限だけ)を入れて、FR-2 の文が出るか(テストは pypdf の RC4 で作った物だけ。AES の物は `cryptography` が無くても `is_encrypted` で断れる想定)。
- 入力欄のある実物の PDF(役所の申請書など)で、入力欄の値が格子に描かれるか(`init_forms`)、まとめたあとも入力できるか。

## 6. 本体担当へのお願い(契約の範囲外なので触っていない)

- `pyproject.toml`: 仕様書 §2 のとおり `pypdf>=6.19,<7` と `pypdfium2>=5.13,<6` に上限を付けてほしい(今は下限だけ)。P-32 の `_add_object` と、`EncodedStreamObject` の内部(`decoded_self`・`_data`)に依るため。
- `deskkit.spec`(H4-11): pypdf・pypdfium2・pypdfium2_raw(`pdfium.dll` と `version.json`)。PagePress はどちらも関数の中で import するので、PyInstaller が拾わない場合は hiddenimports に `pypdf`・`pypdfium2`・`pypdfium2_raw` を足す。pi-heif と numpy(16 ビットの PNG)も使う(v0.3 から入っている)。
- `THIRD_PARTY_LICENSES.txt`(H4-11): pypdf(BSD-3-Clause)、pypdfium2(Apache-2.0 / BSD-3-Clause、データは CC-BY-4.0)、wheel の `BUILD_LICENSES` の PDFium と部品。
- catalog の一言: 仕様書 §2 は「PDF をネットに上げずにまとめる・分ける」、今の catalog は「PDF をネットに上げずにまとめる」。どちらにするかは本体担当の判断で。
- MODULE_GUIDE: P-1(V4-2 の例外は pypdf と pypdfium2 だけ)と、grep 系の AC(AC-16〜AC-18)の対象に `pagepress` を足す。AC-17 の `grep -rln "pypdfium2" deskkit/modules/pagepress` は `__pycache__` の .pyc も拾うので、`--include=*.py` を付けて数える。
- (参考)`deskkit.ui.widgets.FadeStack`(QStackedWidget)は、隠れているページの折り返しの高さまで最小の高さに入れるので、高さの違うページを切り替えると短いページのカードが縦に伸びる。PagePress は FadeStack を使わず、縦に並べて今のタブだけを見せ、フェードは自分で付けた。

- Q-6: 上限。505MB の入力で作業セットが 540〜780MB。1GB のままでよいか(8GB の PC では 1GB 近い入力で遅くなるおそれ)。
