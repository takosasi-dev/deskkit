# PlugSave v0.4.1 — 途中で抜いたときの手当て(担当 C)

対象: `deskkit/modules/plugsave/**`・`tests/modules/plugsave/**`。`docs/INTERFACES_v0.4.1.md` §3 C の 1〜5。
v0.4 の不変条件(`INTERFACES_v0.4.md` §0・PlugSave の INV-*)は緩めていない。バックアップ先のファイルは消さず・上書きせず、
消すのは `staging.py` の中の、自分が作った名前の形の物だけ(AC-20 のテストはそのまま通る)。

## 1. 背景

v0.4.0 で 1MiB 未満のファイルは fsync しないことにした(`copier.FSYNC_MIN_BYTES`。`docs/v0.4/plugsave.md` §7 回答1)。
途中で抜かれると、小さいファイルが中身の欠けたまま最終の名前で残ることがあり、次の回は大きさと更新日時で比べるので気づかない。

## 2. やったこと

| §3 C | 内容 | 場所 |
|---|---|---|
| 1 | **止まった回の印** = その回の一時フォルダ `<PC>\_作業中\<回の ID>\` そのもの。回が終われば消し、止まったら残す。ID は乱数の 32 桁の 16 進で、ファイル名・パスを持たない。止まり方は4つとも残る: 抜いた(`removed`)・DeskKit が落ちた / PC が止まった(回の終わりの処理が走らないので残る)・利用者が止めた(`cancelled` のときは消さない) | `unfinished.py`(新規)・`copier.BackupRun._finish_markers`・`staging.cleanup_leftovers(keep_dirs=True)` |
| 2 | **前の回に書いた小さいファイルの見分け方** = バックアップ先のファイルの**作成日時**が、印の窓 `[印の作成日時 - 2 秒, 印の終わり)` に入り、大きさが 1MiB 未満のもの。計画で「確かめる」(`verify`)に分け、コピーの前に**中身をコピー元と比べ、違う物だけ**古い方を `_以前の版` へ移してコピーし直す。大きいファイル(fsync している)は今のまま見ない | `planner.make_plan(suspect=…)`・`copier._same_content`・`unfinished.build_suspect` |
| 2 | **トンネリングの手当て**: 変わったファイルは、古い版を移した直後に同じ名前へ `.part` を名前の変更するため、Windows が古い版の作成日時を戻す(下の §3)。小さいファイルは名前の変更のあとで作成日時を `.part` を作った時刻へ戻す(`SetFileTime` で作成日時だけ) | `copier._keep_birth`・`unfinished.set_birth_ns` |

| 5 | **テスト**: 偽のドライブ(tmp_path の中のフォルダ)で、抜いた回・落ちた回・やめた回のあとの回で欠けたファイルが直ること、印が壊れている・無いときに落ちないこと | `tests/modules/plugsave/test_unfinished.py`(新規・12 件)、自己検査にも 2 項目 |

### 印の決まり(unfinished.py)

- 印とみなすのは、`_作業中` の中の 32 桁の 16 進の名前の**フォルダ**で、中身が `<数字>.part` と `end` のフォルダだけのもの。
  ほかの物が入っていれば(利用者が置いたなど)PlugSave が片づけられないので印にしない(見ない・触らない)。
- 回の始め: 印を読む → `.part` だけ片づける(フォルダは残す)→ 自分の回のフォルダを作る → 引き継いだ印の中に空の `end` のフォルダを作る。
  `end` の作成日時がその印の窓の終わりになり、この回が書く物は前の回の窓に入らない(この回も止まったら、この回のフォルダが別の印になる)。
- 回の終わり: `ok` で、300,000 件で切り詰めておらず、確かめる物を全部確かめられた(`verify_left == 0`)ときだけ、引き継いだ印を片づける
  (`.part` → `end` → 空のフォルダの順に消す。消すのは `staging.py` の中だけ)。それ以外は印を残し、次の回がもう一度確かめる。
- 計画だけの回(初回の計画)は印を読むだけで、閉じない・片づけない。
- v0.4.0 が残した回のフォルダ(抜いた回)も同じ形なので、v0.4.1 に上げた最初の回で印として扱われる。

## 3. 作成日時の扱い(根拠)

| 事柄 | 内容 | 根拠 |
|---|---|---|
| PlugSave が作るファイルの作成日時 | PlugSave は `CopyFile` を使わず、`.part` を `open(…, "xb")` で**自分で作る**ので、作成日時は「PlugSave が `.part` を作った時刻」になる。コピー元の作成日時は写さない | 実装(`copier.RealIO.open_part`) |
| 名前の変更 | 同じボリュームの中の名前の変更・移動は作成日時を変えない。`.part` → 最終の名前でも保たれる | Microsoft の説明「NTFS の日時」(KB299648: 同じボリュームへの移動は作成日時・更新日時とも変わらない。コピーは作成日時が今になる)。**この PC で測った**: NTFS(C: の一時フォルダ)・exFAT(D:)とも保たれた |
| `os.utime` / `shutil.copystat` | CPython の `os.utime` は Windows で `SetFileTime(h, NULL, &atime, &mtime)` を呼び、作成日時を渡さない。`shutil.copystat` は `os.utime` を呼ぶだけ。どちらも作成日時を変えない | CPython の `Modules/posixmodule.c`(`utime_impl` の Windows の枝)。**測った**: NTFS・exFAT とも `os.utime` の前後で作成日時は同じ |
| Windows のコピー(参考) | エクスプローラー・`CopyFile` でコピーした新しいファイルは、作成日時がコピーした時刻、更新日時は元のまま | KB299648。PlugSave の見分け方はこれに頼らない |
| **トンネリング** | FAT と NTFS は、あるフォルダで名前を消す(削除・名前の変更で外へ移す)と、15 秒以内に同じフォルダで同じ名前を作る・名前の変更で入れると、**消した方の作成日時(と短い名前)を戻す**。PlugSave の「変わった」ファイルはこれに当たり、古い版の作成日時になる | Microsoft KB172190「Windows NT Contains File System Tunneling Capabilities」(既定 15 秒・`MaximumTunnelEntryAgeInSeconds`)。**測った**: NTFS・exFAT とも、古い版を移した直後に `.part` を同じ名前にすると作成日時が古い版の値になった。`SetFileTime` で作成日時だけを戻すと `.part` の値に戻った(差 0) |
| 精度 | NTFS は 100ns。exFAT は作成日時に 10ms の刻み(CreateTimestamp の 2 秒 + Create10msIncrement)と UTC の差を持つ。FAT32 も作成日時に 10ms の刻み(DIR_CrtTime の 2 秒 + DIR_CrtTimeTenth)を持つが、**現地時刻**で持つ | Microsoft の exFAT の仕様(File Directory Entry の CreateTimestamp・Create10msIncrement・CreateUtcOffset)・FAT の仕様(fatgen103 の DIR_CrtTimeTenth)。**測った**: exFAT(D:)で作成日時はすべて 10ms の倍数、NTFS は 100ns 単位。**FAT32 はこの PC に無く測っていない** |
| 時刻の比べ方 | 窓の端は印のフォルダの作成日時で、**同じドライブの同じ時計・同じ刻み・同じ変換**で読んだ値どうしを比べる(モジュールの時計・本物の時計と比べない)。FAT32 の現地時刻も、印とファイルが同じ変換を通るので揃う | 実装。**測った**: フォルダを作った直後に中へ作ったファイルの作成日時はフォルダ以上(NTFS +0.5ms・exFAT +40ms)。作成日時は `time.time_ns()` より少し前になりうる(exFAT −5.7ms・NTFS −0.9ms。刻みの切り捨て)→ 窓の始まりを 2 秒広げた |
| Python で読む | `os.stat().st_birthtime_ns`(Python 3.12 から Windows で使える)。`os.scandir` の `DirEntry.stat()` にも入る(FindFirstFile の値。追加の I/O なし) | **測った**: この PC の Python 3.13.2 で `scandir` と `os.stat` の値が一致 |

**通しの確認(この PC)**: 一時フォルダ(C: の NTFS)と、この worktree の下の一時フォルダ(D: の exFAT。終わったら消した)で、
「落ちた回 → 1 件の中身を 0 にする → 次の回」を本物の部品(`BackupRun`)で行い、どちらも「確かめて同じ 1 件・直した 1 件・変わったファイルの作成日時が戻る・印が片づく・3 回目は印なし」になった。

### 成り立たない場合の扱い

- ファイルシステムが NTFS・exFAT・FAT32・FAT・ReFS 以外、印の作成日時が読めない(0)・`end` の作成日時が読めない、
  印がこの回の一時フォルダより 2 秒以上新しい(時計が戻った)とき → **小さいファイルをすべて確かめる**(`check_all_small`。画面の 1 行は「作成日時で見分けられないため、小さいファイルをすべて確かめ…」)。
  確かめるのは読むだけなので、同じ中身のファイルは書かない・`_以前の版` に増えない。ファイルが多いと時間がかかる。
- バックアップ先のファイルの作成日時が読めない(0)ときは、そのファイルを確かめる。
- 作成日時を戻せなかったとき(`SetFileTime` の失敗)は件数だけをログに出す(`birth_fix_failed`)。そのファイルは、あとの回が止まったときに見分けられないことがある。

### 残る隙(利用者に知っておいてほしいこと)

1. 名前の変更と作成日時を戻す間(マイクロ秒)に抜かれると、その 1 件は古い版の作成日時のまま残り、見分けられない。
2. 回が `ok` で終わって印を消した**直後**に抜くと、まだディスクへ書かれていない小さいファイルがあっても印が無い。
   USB メモリ(「クイック削除」の既定)は閉じたファイルをすぐ書き出すので起きにくい見込み(実機で確かめる。§6 の 4)。
3. 印を作った直後(何も書く前)に抜いてフォルダの作成が残らなかった場合は、何も書いていないので害は無い。

## 4. 仮に決めたこと(利用者に確かめたいこと)

| # | 決めたこと | 理由 |
|---|---|---|
| K-1 | 印は**ドライブ側**(回の一時フォルダ)に置き、`ctx.data_dir` には置かない | 時刻を同じドライブの作成日時どうしで比べられる(時計・刻み・FAT の現地時刻の変換が揃う)。落ちた・PC が止まったときも、何も書かずに残る。v0.4.0 の抜いた回にも効く |
| K-2 | 「やめる」で止めた回も**止まった回**として扱う | 仕様(§3 C-1)。やめたあとすぐ抜かれることがある。やめた回に書いた小さいファイルは次の回に中身を比べる(読むだけ) |
| **K-3** | **「もう一度コピーする」ではなく「中身を比べ、違う物だけもう一度コピーする」** | 無条件にコピーし直すと、中身が同じファイルまで古い方を `_以前の版` へ移すことになり(上書き・削除ができないため)、同じ中身の複製が増えて空きを使う。比べれば、結果(先の中身が正しくなる)は同じで、増えるのは欠けていた物だけ |
| K-4 | 確かめる物は、その回の最初に処理する。始める前の空きの見積もり(B-9)には入れない(違ってコピーし直すときは 1 件ごとの空きの確認 S-16 で見る)。300,000 件の上限(S-3)には数える | 前の回の分を先に直す。確かめるだけの物で「空きが足りません」にしない |
| K-5 | 印を片づけるのは、`ok`・切り詰めなし・確かめ残し 0 のときだけ。それ以外は残し、`end` で窓を閉じる | 手当てが済むまで忘れない。閉じるので、あとの回が書いた物まで毎回確かめ直すことはない |
| K-6 | 確かめて同じだった物は ops・画面の「そのまま」にも数える。コピーし直した物は `new`・`changed` に入れず `recopied` に数え、完了の通知の「コピー N 件」と usage の「コピーしたファイル」には足す | 「そのまま」の意味を保つ。コピーした数は実際に書いた数にする |
| K-7 | 画面の 1 行の文言は `module.unfinished_text` の 5 通り(直した・全部合っていた・確かめ残しあり・その回に書いた物が無い・この回も終わらなかった) | 例の文言(§3 C-3)を、実際に比べる動きに合わせた |
| K-8 | 作成日時を戻すのは 1MiB 未満のファイルだけ | 見分けに使うのは小さいファイルだけなので |

## 6. 実機で確かめること(`docs/v0.4/plugsave.md` §5 に足す)

1. **FAT32 の USB メモリ**で、コピーしたファイルの作成日時(`os.stat(p).st_birthtime_ns`)が 10ms の刻みで、回のフォルダの作成日時以上になること。
   変わったファイルの作成日時が、古い版の値ではなく書いた時刻になること(トンネリングの手当て。ログに `birth_fix_failed` が出ないこと)。
2. FAT32・exFAT・NTFS の本物の USB で、コピーの途中で抜く → 挿し直す → 次の回の「前回の結果」に 1 行が出て、印(`_作業中\<32桁>`)が片づくこと。
   抜いたときに中身の欠けたファイルが実際にできたか(確かめた数・直した数)を記録する。
3. 回の途中で DeskKit をタスクマネージャーで終わらせる・PC の電源を切る → 次の回で同じように確かめること。
4. 回が `ok` で終わった**直後**に抜いたとき、最後の方の小さいファイルが欠けないこと(残る隙の 2)。USB メモリの「クイック削除」と、外付け SSD(「高パフォーマンス」)の両方。
5. 作成日時の違う時間帯(夏時間のある地域の設定)で FAT32 に書いたあと、時間帯を変えても見分けが揃うこと(印とファイルが同じ変換を通るので揃う見込み)。
6. 小さいファイルがとても多いドライブ(1 万件以上)で、作成日時が使えないときの「すべて確かめる」にかかる時間。
