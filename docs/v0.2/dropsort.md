# DropSort v0.2.0 の変更点

仕様書(DropSort 実装仕様書 v1)と MODULE_GUIDE.md からの差分・既定値・理由。契約は `docs/INTERFACES_v0.2.md`。

## 1. CLI と停止を GUI スレッドから外した(不具合修正)

| 変更 | 理由 |
|---|---|
| `handle_cli` は `run_command` を作業スレッド(スキャンと同じ1本)で実行し、メインスレッドではローカルの `QEventLoop` を回して終わるのを待つ。IPC の応答は処理が終わってから返す | `sort-existing --apply` や別ドライブへのコピーを伴う `undo` の間、トレイ・ホットキー・他モジュールが固まっていた。ロック待ち(最大10秒)もメインスレッドで起きていた |
| `stop()` は停止を要求(`service.cancel`)し、作業スレッドを最大 **5 秒**(`STOP_WAIT_S`)だけ待つ | `ex.shutdown(wait=True)` でメインスレッドが無制限に止まっていた |
| スキャン・`sort-existing`・`archive-now`・`undo` は、次のファイルへ進む前に停止要求を見る。ファイル1件の移動(別ドライブのコピー→検証→元の削除を含む)は途中で打ち切らない | 途中で止めると「コピーだけある」「検証前」の状態が残りうる。5 秒を超えたら待つのをやめて戻り、作業スレッドはその1件を終えてから止まる(プロセス終了時は Python が作業スレッドの終了を待つ)。残りのファイルは次のスキャンで扱う(判断は毎回フォルダの実状態から行うので取りこぼさない) |

## 2. D1 ルールを試す

- ルール欄の下に「ルールを試す」を置いた。ファイル名・サイズ・入手元の印(MOTW なし / ゾーン 0〜4 / ゾーン不明)・入手元ドメイン(任意)を入れると、当たるルール・試運転か本番か・行き先の予定(テンプレートは展開済み)・他のルールが当たらない理由(最初に外れた条件)を表示する。
- 判定は実際の評価と同じ関数を使う(`rules.explain()` を新設し、`matches()` はこれを呼ぶ形にした)。一時ファイル名・危険名(二重拡張子など)・無効なルール・未接続の移動先・MOTW を保てない FS も注記する。
- ファイルには触らない(`tester.simulate` は Win32 層を受け取らない)。入力したドメインや貼り付けた URL は判定に使うだけで、ログ・操作ログ・設定には書かない(URL からはドメイン名だけ取り出す)。

## 3. D2 移動先テンプレート

- ルールの移動先に `{yyyy}` `{mm}` `{dd}` `{ext}` `{domain}` を書ける(大文字小文字は問わない)。例: `D:\整理\{yyyy}\{mm}`、`D:\整理\{ext}`、`D:\入手元\{domain}`。
- **基準フォルダ** = 最初のプレースホルダを含む階層の親(`D:\整理\img_{yyyy}` なら `D:\整理`)。基準フォルダは利用者が決めたものなので、ルールの検査(存在・ネットワーク・ダウンロード自身・アーカイブ配下)は基準フォルダに対して行い、**自動では作らない**(仕様書 §9.2「dest はフォルダを作成しない」を基準フォルダについて守る)。無ければ従来どおりルールを無効化し、編集画面の「フォルダを作成」でだけ作る。
- 自動で作るのは基準フォルダの**下**だけ。移動の直前に:
  1. 展開後のパスが基準フォルダ(実パス)の下であることを確かめる。
  2. すでにある途中のフォルダの最終パスが基準フォルダの外(リンク・ジャンクション)なら `refused` / `dest_escape`(INV-11)。
  3. 足りないフォルダを上から順に作る(失敗は `failed` / `dest_create_failed`)。
  4. 展開後のパスに `check_dest` をかけ直す(ネットワーク・ダウンロード自身・アーカイブ配下なら `refused`、理由コードは check_dest のもの)。
- 展開した値は1階層ずつ無害化する: Windows で使えない文字と制御文字は `_`、予約名(CON・NUL・COM1 など。`nul.txt` のような形も)は先頭に `_`、末尾の点と空白は削る、空・`.`・`..` は `_`、1階層 120 文字まで。値が区切り文字を作ることはない。
- 既定値: `{domain}` が分からない(MOTW なし・HostUrl なし)ときは `unknown`、拡張子が無いときは `noext`。
- 日付(`{yyyy}` `{mm}` `{dd}`)は **ファイルがダウンロードフォルダに来た時刻**(作成時刻。取れなければ更新時刻)。理由: 処理した日だと `sort-existing` で古いファイルが全部今日の日付に入る(D-11 と同じ問題)。更新時刻はブラウザがサーバー側の日時にする可能性がある(仕様書 Q-6 未確認)。
- 試運転ではフォルダを作らない(基準フォルダの FS で拒否予定かどうかを判定し、行き先は展開後のパスを記録する)。
- 元に戻す(undo)は作ったフォルダを消さない(DropSort はフォルダを削除する処理を持たない)。
- 操作ログ・試運転ログの `dst` には展開後のパスが入るので、`{domain}` を使うとドメイン名がパスとして記録される(ガイドどおりドメイン名のみ。URL は入らない)。
- テンプレートの形の検査(知らないプレースホルダ・括弧の対応・基準フォルダがドライブ文字から始まる絶対パスか・空の階層や `..`・使えない文字・予約名)はルールの読み込み時に行い、不正ならそのルールだけ無効化する。編集画面は同じ検査をその場で出し、今日の日付・`example.<拡張子>`・`example.com` での展開例を見せる。
- 制約: フォルダ名に `{` `}` をそのまま使うことはできない(テンプレートとして解釈する)。

## 4. D3 ルールの実績と本番化の提案

- ルールカードに直近 **14 日**の実績を出す。試運転: 「試運転 14日で N 件の予定・拒否予定 K 件」。本番: 「本番 14日で N 件を移動・取り消し M 件(・拒否/失敗 P 件)」。
- 試運転のルールが **予定 5 件以上**・**最初の試運転の記録から 7 日以上**・**拒否予定 0・拒否/失敗 0・取り消し 0**・ルールが有効、を満たすと「本番へ切り替え」ボタンを出す。押すと従来の確認ダイアログ(移動予定の件数つき)を経て切り替える。自動では切り替えない。
- 集計は `dryrun.jsonl` と `oplog.jsonl` の**末尾 16 MB ずつ**だけを読み、作業スレッドで行う。結果はログのサイズ・更新時刻と時刻(1時間単位)が変わるまでキャッシュする。ルールはルール名で数える(名前を変えると実績は引き継がない)。undo の失敗(`source: undo`)は問題に数えない。

## 5. M3 モード連携(このモード中は止める)とスヌーズ

- 設定 `pause_in_modes: list[str]`(既定 `[]`)。詳細設定の「モード連携とスヌーズ」で `ctx.list_modes()` のモードをチェックで選ぶ。今の ModeShift の設定に無いモード名も消さずに残し、「(今の ModeShift の設定にありません)」と表示する。
- 契約 §2 どおり、`modeshift.switched` の `mode` がリストにあれば自動の整理(スキャン・移動・試運転の記録・自動アーカイブ)を止め、`modeshift.reverted` かリスト外のモードへの `switched` で再開する。設定からそのモードを外したときもその場で再開する。
- スヌーズ中(`ctx.is_snoozed()`)も自動の整理を止める。`host.snooze_changed` で `snoozed: false` を受けたら再開する。
- 再開したときは**フルスキャン**を1回行う。止まっている間に来たファイルも、判断はフォルダの実状態から行うので取りこぼさない(完了判定の待ち時間は再開後に数え始める)。
- 止めた・再開したことは通知しない。ページのヒーローの状態ピル(「停止中: モード「…」」「停止中: スヌーズ」)とトレイの状態行にだけ出す。
- 利用者が押した操作は止めない(契約 §1): 「今すぐスキャン」(トレイ・ページ)は停止中でも1回動く。元に戻す・既存ファイルの整理・アーカイブの今すぐ評価・CLI も動く。DropSort 自身の「一時停止」は従来どおり「今すぐスキャン」も止める。
- 今のモードはイベントで知るだけで保存しない。DeskKit を再起動した直後は、次の `switched` が来るまで止めない。
- 本体が古く `is_snoozed` / `list_modes` / `on` が無い場合は、止めない側に倒して動く。

## 7. その他

- アーカイブの試運転表示で、まだ無い月フォルダの行き先の名前に ` (1)` が付いて見えることがあった(ダウンロードフォルダ自身で名前の衝突を調べていた)のを直した。行き先のフォルダがまだ無ければ元の名前のまま表示する。
- 新しい理由コード: `dest_escape`(テンプレートの行き先がリンクで基準フォルダの外を指す)、`dest_create_failed`(行き先のフォルダを作れない)。
- selftest に「移動先テンプレート(基準フォルダの下だけ作る)」を追加(12 項目)。

## 契約への提案

- `modeshift.switched` / `reverted` だけでは、DeskKit の起動直後に「今どのモードか」が分からない(ModeShift が起動時に今のモードを `switched` で知らせるか、`ctx.current_mode()` があると、再起動をまたいでも「このモード中は止める」が効く)。
