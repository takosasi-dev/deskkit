# ClipShelf v0.2.0 — 仕様書からの変更点

対象: `deskkit/modules/clipshelf/**`。仕様書(ClipShelf 実装仕様書 v1)と `docs/MODULE_GUIDE.md` からの差分だけを書く。
逸脱不可要件(INV-1〜9)・C-1〜C-12 は変えていない。DB のスキーマ(§9.3)も変えていない。

## 1. 変更点の一覧

| # | 変更 | 既定値 | 理由 |
|---|---|---|---|
| B-1 | 保持上限(件数・日数)のスピンボックスは、値が 700ms 落ち着いてから判定し、今ある履歴が消えるときは件数を示して確認する。取消で元の値に戻す | — | ホイールや押し間違いで、取り消せない削除(D-14)が即座に走っていた。本体のホイール対策(UX-1)には頼らない |
| B-2 | 全消去は DB の履歴の行を SQL で直接消す。復号できない履歴の行も(ピンの列に関係なく)消す | — | メモリに読めた行だけを消していたため、別ユーザー・別プロファイルの行が残り、起動時の「全消去を検討してください」が消えなかった |
| C1 | 定型文のプレースホルダに `{input:ラベル}`・`{input:ラベル=既定値}`・`{select:A\|B\|C}` を追加。パレットで選ぶと、パレット内のフォームで値を聞いてから貼り付ける | — | 利用者の指示(v0.2 の C1)。仕様書 §8.6「8.4 に無いプレースホルダを実装しない」からの意図した逸脱 |

| S | 本体のスヌーズ中は記録しない(`ctx.is_snoozed()`) | — | 契約 §1 |

## 2. 詳細

### B-1 保持上限の誤操作対策
- `valueChanged` のたびに 700ms の単発タイマーを張り直し、切れたときに件数・日数をまとめて判定する(`page.RETENTION_DEBOUNCE_MS`)。
- 消える件数は `Store.trim_preview()`(消さない)で数える。0 件なら確認なしで保存。N 件なら「N 件を削除して保存」の確認ダイアログ。
- 取消・保存失敗のときはスピンボックスを設定の値に戻す(シグナルを止めて戻すので、再判定は起きない)。
- 起動時・記録のたびの保持上限(FR-8)は従来どおり。

### B-2 全消去
- `DELETE FROM items WHERE kind='history' AND (pinned=0 OR <ピンも消す>)` に加え、復号できなかった履歴の行を id で消す。定型文は(復号できないものも含めて)消さない。
- 起動時の警告は履歴と定型文で分けた。履歴の分だけ「全消去で削除できます」と案内する。確認ダイアログにも復号できない件数を出す。
- ページの「復号できない行」ピルは件数が 0 になれば消える。

### C1 定型文の入力欄・選択欄
- 書式: `{input:ラベル}` / `{input:ラベル=既定値}` / `{select:A|B|C}`。`{{input:x}}` は従来どおり文字の `{input:x}`。
- 同じラベルの `{input:…}` は1つの欄にまとめ、同じ値を全部の出現箇所に入れる(最初に出た既定値を使う)。同じ選択肢の `{select:…}` も1つにまとめる。選択欄のラベルは「選択 1」「選択 2」…。
- 選択肢の無い `{select:}` は欄にせず、そのまま残して警告する。未知の `{name}` は従来どおり(FR-16)。
- パレット: 聞く欄のある定型文で Enter → パレット内にフォーム(左に欄、右に貼り付ける内容のライブプレビュー)。Tab / Shift+Tab で欄を巡回、Enter で貼り付け、Esc で一覧へ戻る。最初の欄は既定値を全選択した状態でフォーカス。
- 値は展開してクリップボードに書くだけ。ログ・ops.jsonl・DB・設定に書かない(INV-1/2)。フォームの部品は貼り付け・戻る・パレットを閉じるときに消す。値の中の `{…}` は再展開しない(1回だけ置換)。
- 編集画面(ページ・ダイアログ)に `{input:ラベル}` `{select:A|B|C}` のチップを追加。挿入後はラベル部分を選択状態にする。プレビューでは欄を〔ラベル〕で表示する。

### C2 変換して貼り付け
- 変換(番号順): 1 前後の空白を除く / 2 改行を除く(スペースに)/ 3 全角英数を半角に / 4 大文字 / 5 小文字 / 6 1行目だけ。
  - 「改行を除く」: 改行(CRLF・CR・LF)とその前後の空白を半角スペース1つにする。連続する改行・空行も1つにまとめる。
  - 「全角英数を半角に」: 全角の英字・数字(Ａ-Ｚ ａ-ｚ ０-９)だけ。記号・カナ・全角スペースは変えない(日本語の括弧などを壊さないため)。
  - 「1行目だけ」: 空白だけの行を飛ばした最初の行(行末の空白は除く)。
- パレットで Shift+Enter → 変換の一覧(↑↓・数字 1〜6・Enter・Esc)と変換後のプレビュー。右クリックメニューにも「変換して貼り付け」のサブメニュー。
- 聞く欄のある定型文は、変換を選んだ後にフォームを出す(フォームのプレビューは変換後の内容)。
- 書き込みは `writer.py` 経由で自己印(Origin)つき。自分の書き込みとして再記録しない。`{clipboard}` の除外形式も引き継ぐ(INV-7)。変換結果が空なら書かずに知らせる。
- ops.jsonl: `{"op": "transform_paste", "transform": "<ID>"}`(本文・文字数は書かない)。

### C3 アプリ別の短命記録
- 設定 `short_lived.exes`(exe 名、大文字小文字無視)と `short_lived.minutes`(1〜10080 分)。GUI の「短命記録(アプリ別)」カードで編集(実行中のアプリから選ぶボタンあり)。
- 所有者 exe が分かり、かつリストにあるときだけ、記録時に `expires_at = 記録時刻 + minutes` を付ける。判定は exe 名だけで、内容は見ない。所有者不明で記録したもの(`unknown_owner_policy: record`)には付けない。
- 期限は暗号化した payload の JSON に `expires_at` として入れる(§9.3 の平文の列は増やさない。v0.1 の payload はキーが無いだけで読める)。読めない期限は期限切れ扱い。
- 掃除: 起動時・1分ごとのタイマー・パレットを開くとき。ピン留めした項目は消さない(利用者が明示的に残したもの)。記録済みの項目の期限は、後から設定を変えても変わらない。
- ops.jsonl: `{"op": "expired", "deleted": N}`、ログ: `expired deleted=N`(件数だけ)。

### M3 モード中は記録しない
- 設定 `pause_in_modes: list[str]`(モード名)。GUI では `ctx.list_modes()` をチェックリストで出し、今は ModeShift に無いモード名も消さずに「見当たらないモード」として残す。
- `modeshift.switched` の `mode` がリストにあれば停止、`modeshift.reverted` かリスト外への `switched` で再開(契約 §2)。停止中の更新は判定理由 `paused`(§9.4 の語彙は増やさない)で、本文は読まない(INV-3)。
- 止めた・再開したは通知しない。ページのヒーローのピル・カードの状態文・トレイの状態文(「モード中のため停止(記録しない)」)にだけ出す。
- 最後に受けたモード名を `data_dir/mode_state.json` に残し、モジュール・アプリの再起動をまたいで停止状態を保つ(ModeShift も現在のモードを保存しているため)。復帰イベントを取りこぼしたときのために、カードに「停止を解除」ボタンを置いた。
- ログにモード名は出さない(`recording paused by mode` / `resumed`)。

### スヌーズ
- 記録の入口(`monitor` の一時停止判定)で `ctx.is_snoozed()` を見る。利用者の明示操作(パレットでの選択・書式なし化・全消去・CLI)は止めない。
- 状態文は「スヌーズ中(記録しない)」。`host.snooze_changed` を受けたときと、1分ごとの定期処理で状態文を直す。
- `is_snoozed` / `list_modes` が無い本体(v0.1)や、呼び出しが例外を投げた場合は「スヌーズではない」「モードなし」として動く。

### 記録を止める理由の優先順
状態文は 一時停止(手動) > スヌーズ > モード の順で1つ出す。`status` CLI には `stopped_by=manual,snoozed,mode` のように全部出す。

### diagnostics()
`mode`・`store_ok`・`history`・`pinned`・`snippets`・`undecryptable`・`short_lived_items`・`short_lived_apps`(件数)・`recording_paused`・`paused_reasons`(`manual,snoozed,mode` の組み合わせか `none`)・`pause_in_modes`(件数)・`exclude_apps`(件数)・`unknown_owner_policy`・`auto_paste`・`hotkeys_failed`(件数)。本文・exe 名・モード名・パスは入れない。

## 3. 追加した設定キー(既定値)

```json
{
  "pause_in_modes": [],
  "short_lived": {"exes": [], "minutes": 10}
}
```
足りないキーは起動時に既定値で補って書き戻す(従来どおり)。

|---|---|

| `transform_paste` | `transform`(変換の ID) |

## 5. 契約(INTERFACES_v0.2)について

- 契約どおり `modeshift.switched` / `modeshift.reverted` / `host.snooze_changed` を購読している。この枝の `events.py` にはまだ `modeshift.reverted` と `host.snooze_changed` が無い(本体担当が追加する前提)。無い間は購読が警告になるだけで、モード中の停止は「リスト外への switched」でしか解けない。
- **契約変更の提案**: 受信側が起動した時点の現在モードを知る手段が無い(ModeShift は現在モードを保存しているが、モジュール同士は import できない)。`ctx.current_mode() -> str | None`(本体が ModeShift の状態を読む)か、ModeShift が起動時に現在モードで `modeshift.switched` を再送する取り決めがあると、ClipShelf 側の `mode_state.json` が不要になり、取りこぼしも起きない。
